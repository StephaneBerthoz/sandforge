# Plan 01: Test Infrastructure — MockBridge + Shared Fixtures

## Objective

Build the foundational test infrastructure that all subsequent E2E plans depend on. The MockBridge wraps the existing `injectVSCodeApiMock` + `sendExtensionMessage` pattern into a higher-level API that auto-correlates request/response messages. Shared fixtures eliminate duplicated mock data across specs. Also install `@axe-core/playwright` for Plan 03.

## Context

- Existing helpers in `e2e/mocks/vscode-api.ts`: `injectVSCodeApiMock()` and `sendExtensionMessage()` — keep these as the low-level layer
- Multiple specs duplicate `resolveOrgListLoading()` and inline mock org data — extract to shared fixtures
- `__SANDFORGE_MESSAGES__` global captures outgoing messages — MockBridge should use `page.waitForFunction()` instead of `waitForTimeout(200)` to wait for requests
- Message types are defined in `packages/shared/src/types/messages.types.ts` — import types for fixture type safety
- Current specs in `e2e/`: home-page, navigation, accessibility, i18n, responsive, theme, seed, sync, monitor, compare, dataops, automation — all must keep passing

<name>Create MockBridge helper</name>
<files>

- packages/webview/e2e/helpers/index.ts

<action>
Create `MockBridge` class that wraps the existing VSCode API mock pattern:

1. `MockBridge.setup(page)` — calls `injectVSCodeApiMock(page)`, stores page reference
2. `bridge.waitForMessage(type)` — uses `page.waitForFunction()` to wait for a message of the given type in `__SANDFORGE_MESSAGES__`, returns the message (including its `id` for correlation). No `waitForTimeout`.
3. `bridge.respond(type, payload, correlationId?)` — calls `sendExtensionMessage` with auto-generated `id`. If `correlationId` not provided, auto-extracts it from the last captured message of the corresponding request type.
4. `bridge.respondToNext(requestType, responseType, payload)` — convenience: waits for a message of `requestType`, then sends `responseType` response with auto-correlated `id`. This replaces the `resolveOrgListLoading` pattern.
5. `bridge.getMessages(type?)` — returns captured messages, optionally filtered by type.

Keep `injectVSCodeApiMock` and `sendExtensionMessage` as re-exports from the helpers index for backward compatibility.

Export `MockBridge` from `helpers/index.ts`.
</action>
<verify>
- `packages/webview/e2e/helpers/MockBridge.ts` exists and exports MockBridge class
- `packages/webview/e2e/helpers/index.ts` re-exports MockBridge plus legacy helpers
- MockBridge uses `page.waitForFunction()` not `waitForTimeout`
</verify>
