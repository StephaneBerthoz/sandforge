# Plan 02: AI & Autopilot E2E Specs

## Objective

Create E2E test specs for the two modules that have zero coverage: AI and Autopilot. These specs use the MockBridge helper from Plan 01, serving as reference implementations of the new test pattern. Cover all sub-features with multiple response scenarios (success, partial, error, timeout).

## Context

### AI Module
- Pages: `AIPage.tsx` (conversation management), `AIChatPanel.tsx` (chat UI)
- data-testids: `ai-chat-panel`, `conversation-sidebar`, `new-conversation-btn`, `conversation-list`, `no-conversations`, `conversation-item-{id}`, `delete-conversation-{id}`, `chat-empty-state`, `messages-container`, `no-messages`, `message-{id}`, `message-bubble-{role}`, `loading-indicator`, `chat-input-area`, `chat-input`, `send-btn`
- Request types: `ai:chat`, `ai:conversation:create`, `ai:conversation:load`, `ai:conversation:delete`, `ai:nl2soql`, `ai:resolve-error`, `ai:suggestions`, `ai:anomaly-scan`
- Response types: `ai:chat:response`, `ai:conversation:created`, `ai:conversation:loaded`, `ai:nl2soql:response`, `ai:resolve-error:response`, `ai:error`

### Autopilot Module
- Pages: `AutopilotPage.tsx` with wizard (4 steps), graph, control panel, compliance report
- Wizard steps: `Step1_Connect` → `Step2_Objects` → `Step3_Compliance` → `Step4_Review`
- States: connect → objects → compliance → review → executing → completed
- data-testids: `autopilot-page`, `step1-connect`, `autopilot-graph-area`, `control-panel`, `control-tabs`, `control-tab-{id}`, `control-actions`, `control-pause-resume`, `control-skip`, `control-retry`, `view-compliance-report`, `back-from-report`
- Request types: `autopilot:scan-schema`, `autopilot:generate-plan`, `autopilot:execute`, `autopilot:pause`, `autopilot:resume`, `autopilot:skip-node`, `autopilot:override-rule`
- Response types: `autopilot:schema-result`, `autopilot:plan-ready`, `autopilot:node-progress`, `autopilot:node-completed`, `autopilot:node-failed`, `autopilot:completed`, `autopilot:compliance-report`

### MockBridge Pattern (from Plan 01)
```typescript
const bridge = new MockBridge();
await bridge.setup(page);
await page.goto('/');
// Auto-respond to org:list on mount
await bridge.respondToNext('org:list', 'org:list:response', { orgs: MOCK_ORGS });
```

### Existing Spec Pattern to Follow
- `test.describe` blocks per feature area
- `test.beforeEach` with bridge setup + navigation
- `getByTestId()` for selectors, `toBeVisible()` / `toBeEnabled()` / `toBeDisabled()` for assertions
- Message capture verification via `bridge.getMessages(type)`
