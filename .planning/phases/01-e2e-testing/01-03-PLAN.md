- WCAG 2.1 AA target: use `withTags(['wcag2a', 'wcag2aa'])` in AxeBuilder

**1. Create `axe-helper.ts`:**

Export a reusable function:
```typescript
import AxeBuilder from '@axe-core/playwright';
import type { Page } from '@playwright/test';

export async function checkAccessibility(page: Page, options?: { exclude?: string[], disableRules?: string[] }) {
  let builder = new AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa']);
  if (options?.exclude) {
    for (const selector of options.exclude) {
      builder = builder.exclude(selector);
    }
  }
  if (options?.disableRules) {
    builder = builder.disableRules(options.disableRules);
  }
  return builder.analyze();
}
```

Re-export from `helpers/index.ts`.

**2. Create `axe-accessibility.spec.ts`:**

For each navigable page:
1. Setup MockBridge + navigate to page
2. Wait for page to fully render (wait for primary data-testid)
3. For pages needing org data, use `bridge.respondToNext('org:list', ...)` with MOCK_ORGS
4. Run `checkAccessibility(page)`
5. Assert `results.violations.length === 0`

Pages to test (each as its own `test()`):
- Home page (`home-page`)
- Forge/Seed page (`forge-page`) — navigate via sidebar, provide mock orgs
- Sync page (`sync-page`)
- Monitor page (`monitor-page`)

Use `test.describe('axe-core WCAG 2.1 AA', ...)` as the top-level block.

**3. Handle violations:**

If axe reports violations on the first run:
- For **color-contrast**: Check if it's due to missing VSCode CSS variable values in the E2E environment. If so, add CSS variable defaults in the Vite E2E HTML template or mock them via `page.addStyleTag()`. If a genuine contrast issue, fix the component.
- For **other violations**: Fix the source component directly (add aria-labels, fix heading hierarchy, etc.).
- Do NOT use a baseline/snapshot approach. Fix all violations.
- If a violation is genuinely unfixable without major refactoring (e.g., third-party library issue), document it as a `disableRules` exception with a comment explaining why.
