# Plan 2: Quick Seed Flow -- 1-Click Execute with Smart Suggest Defaults

## Objective

Build the Quick Seed end-to-end flow that connects the template gallery (from Plan 01) to execution. When a user clicks "Start Seeding" in the customization modal, they enter Quick Seed mode: pick a target org, then immediately execute using the template's field rules as Smart Suggest defaults (QSEED-02). Progress is shown via the existing `Step7Execute` component, and results via the existing results section in SeedPage (QSEED-03). The user never sees field configuration unless they exit Quick Seed and use the full wizard.

## Context

- **Plan 01 delivers**: `TemplateGallery` + `TemplateCustomizeModal` that call `onSelectTemplate(template, customizedCounts)` when the user confirms. This plan wires that callback to the execution flow.
- **Execution bridge**: `seed:execute` message accepts a payload built from `SeedTemplate` -- see `useSeedExecution.ts` which calls `useBridgeMutation<SeedExecutionResult>('seed:execute', ...)`. The payload needs `orgId`, `objects` (array of `SeedObjectConfig`), and `dryRun`.
- **Smart Suggest defaults (QSEED-02)**: The template already contains complete field rules in each `SeedObjectConfig.fieldRules`. Quick Seed sends these directly to `seed:execute` without any user modification. The user only customizes record counts (from Plan 01's modal), not field rules.
- **Step7Execute props**: `{ isRunning, objectProgress, overallPercent, elapsedMs }` -- reuse this component directly for progress display.
- **Results section**: Currently inline in SeedPage step 3 (lines 349-420). Extract or reuse that JSX block. The results display `SeedExecutionResult` with per-object success/fail breakdown.
- **Org selection**: Reuse the existing org selector pattern from SeedPage step 0 (Select component with orgs from `useOrgStore`).
- **State machine**: Quick Seed has 4 states: `idle` (gallery visible), `selectOrg` (user picks target org), `executing` (seed running), `results` (execution complete). This is simpler than the full wizard.
- **SeedPage integration**: Add a `quickSeedMode` state. When `onSelectTemplate` fires, enter Quick Seed mode and hide the wizard. When the user clicks "Back to Gallery" from results, reset to idle.

<action>
Create a `useQuickSeed` hook that manages the Quick Seed state machine:

```typescript
type QuickSeedPhase = 'idle' | 'selectOrg' | 'executing' | 'results';

interface QuickSeedState {
  phase: QuickSeedPhase;
  selectedTemplate: SeedTemplate | null;
  customizedCounts: Record<string, number>;
  selectedOrgId: string;
  isRunning: boolean;
  executionResult: SeedExecutionResult | undefined;
  objectProgress: ObjectProgress[];
  overallPercent: number;
  elapsedMs: number;
  error: string | null;

  // Actions
  startQuickSeed: (template: SeedTemplate, counts: Record<string, number>) => void;
  selectOrg: (orgId: string) => void;
  execute: () => void;
  reset: () => void;
  setError: (e: string | null) => void;
}
```

Implementation details:
1. `startQuickSeed(template, counts)` -- stores the template and customized counts, transitions to `selectOrg` phase.
2. `selectOrg(orgId)` -- stores the org ID. Does NOT auto-execute (user must click a "Start" button).
3. `execute()` -- Builds the seed payload from the template:
   - Map `template.objects` to `SeedObjectConfig[]`, overriding `recordCount` with `customizedCounts[obj.objectApiName]` where present.
   - Field rules come directly from the template (QSEED-02 -- Smart Suggest defaults).
   - Calls `useBridgeMutation<SeedExecutionResult>('seed:execute', ...)` with `{ orgId, objects, dryRun: false }`.
   - Transitions to `executing` phase.
4. On execution complete, transitions to `results` phase with `executionResult`.
5. `reset()` -- clears everything, returns to `idle`.
6. Derive `objectProgress` from template objects (pending/running/done based on execution state).
7. Track `elapsedMs` with a simple interval while `isRunning`.

For the test file, write at least 4 tests:
- startQuickSeed transitions to selectOrg phase
- selectOrg stores the orgId
- execute builds correct payload with customized counts and template field rules
- reset returns to idle and clears all state
