# Plan 1: Template Gallery UI & Record Count Customization

## Objective

Build the template picker gallery (STPL-04) and record count customization modal (STPL-05) on the SeedPage. The gallery displays pre-built templates (from `PREBUILT_SEED_TEMPLATES`) and user-saved templates (from `seed:template:list`) as cards in a responsive grid. Each card shows name, description, object count, total records, and a "Use This" button. Clicking "Use This" opens a customization modal where the user can adjust record counts per object before proceeding to execution.

## Context

- **Pre-built templates** are defined in `packages/shared/src/constants/seed-templates.ts` -- 3 templates: SALES_CLOUD_STARTER (7 objects, 7601 records), SERVICE_CLOUD_STARTER (5 objects, 3800 records), MINIMAL_DEMO (3 objects, 350 records).
- **Template names/descriptions** use i18n keys (e.g., `seed.templates.salesCloudStarter.name`) -- the gallery must resolve these via `t()`.
- **Saved templates** are loaded via bridge message `seed:template:list` which returns `{ templates: Array<{ id, name, description, tags, updatedAt, objectCount, totalRecords }> }`. Pre-built templates are NOT in the store -- they come from the constant array.
- **SeedPage current structure**: 4-step wizard (select, configure, execute, results). The gallery should appear as a section ABOVE the wizard stepper when on step 0, giving users a "Quick Seed" entry point. If the user clicks "Use This", the flow transitions to Quick Seed mode (handled in Plan 02).
- **The customization modal** receives a `SeedTemplate` and lets the user change `recordCount` per `SeedObjectConfig`. It does NOT allow changing field rules (that is the full wizard). It shows object name, current count, and an editable input. It has "Cancel" and "Start Seeding" buttons.
- **UI components available**: Card, CardHeader, CardBody (from `../../components/ui/Card`), Badge, Button, Input, Modal/Dialog pattern (check if a Modal component exists, otherwise use a simple overlay pattern consistent with the codebase).
- **Pattern reference**: Follow the same hook + component split as existing Seed page (e.g., `useSeedWizardState` + `SeedPage`).

Create a hook `useTemplateGallery` that:

1. Imports `PREBUILT_SEED_TEMPLATES` from `@sandforge/shared` (the constant array).
2. Uses `useBridgeQuery` (or `useBridgeMutation`) to call `seed:template:list` on mount to fetch saved templates.
3. Merges pre-built templates (mapped to a common `TemplateGalleryItem` shape) with saved templates into a single array.
4. The `TemplateGalleryItem` interface:
   ```typescript
   interface TemplateGalleryItem {
     id: string;
     name: string;        // i18n key for pre-built, plain string for saved
     description: string;  // i18n key for pre-built, plain string for saved
     objectCount: number;
     totalRecords: number;
     tags: string[];
     isPrebuilt: boolean;
     updatedAt: string;
     template: SeedTemplate | null;  // full template for pre-built, null for saved (load on demand)
   }
   ```
5. For pre-built templates, compute `objectCount` from `template.objects.length` and `totalRecords` from `sum(template.objects[*].recordCount)`.
6. Provides `loading` boolean and `error` string state.
7. Provides a `loadFullTemplate(id: string): Promise<SeedTemplate>` function that calls `seed:template:load` for saved templates, or returns the pre-built template directly.
8. Provides a `refresh()` function to re-fetch the saved templates list.

Export `TemplateGalleryItem` type and `useTemplateGallery` hook.

- Returns pre-built templates when no saved templates exist
- Merges pre-built and saved templates
- Computes correct objectCount and totalRecords for pre-built templates
- loadFullTemplate returns pre-built template directly without bridge call
