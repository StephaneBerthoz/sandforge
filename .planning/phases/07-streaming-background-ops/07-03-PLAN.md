# Plan 03: Handler Integration & Wiring

## Objective

Wire the streaming pipeline (Plan 07-01) and background registry (Plan 07-02) into the actual sync and seed handlers, create an `ExecutionHandler` for abort/status control, wire everything in `extension.ts`, and add VSCode native notifications for background completion.

## Context

- **SyncOpsHandler.handleExecute()** (line 236-565): Currently blocks until sync completes. The entire try/catch/finally block runs inline. Refactor to: build orchestrator, register execution promise in BackgroundOperationRegistry, return immediately.
- **SeedOpsHandler.handleExecute()** (line 317+): Same blocking pattern. Same refactoring needed.
- **Streaming threshold**: 10,000 records per object. Below: use existing sequential path. Above: use StreamingPipeline + ChunkedBulkExecutor.
- **BackgroundOperationRegistry** from Plan 07-02: Wire into handlers via `HandlerDeps` injection. The registry is created in `extension.ts` and passed to handlers.
- **Native notifications**: `vscode.window.showInformationMessage()` — never used before in this codebase. Add via a `NotificationService` abstraction for testability.
- **ExecutionHandler**: New domain handler for `execution:abort`, `execution:status`, `execution:list` messages. Routes to BackgroundOperationRegistry.

<action>
**ExecutionHandler** — new domain handler:

```typescript
const EXECUTION_TYPES = new Set(['execution:abort', 'execution:status', 'execution:list']);
```

**Class `ExecutionHandler implements DomainHandler`**:
- Constructor takes `deps: HandlerDeps` + `registry: BackgroundOperationRegistry`.

- **`handle(msg: BaseMessage): Promise<boolean>`**: Routes by msg.type.

- **`handleAbort(msg)`**:
  1. Extract `operationId` from payload.
  2. Call `registry.abort(operationId)`.
  3. Send `execution:abort:response` with `{ success: true }`.
  4. If operation not found: send error.

- **`handleStatus(msg)`**:
  1. Extract `operationId` from payload.
  2. Get operation from registry.
  3. Send `execution:status:response` with `ActiveOperation` shape.

- **`handleList(msg)`**:
  1. Get all operations from registry via `getActiveOperations()`.
  2. Send `execution:list:response` with `{ operations: ActiveOperation[] }`.

Add message types to `messages.types.ts` if needed (or use dynamic typing like SmartActionHandler).

**Tests**:
1. handleAbort calls registry.abort() and sends response
2. handleAbort for unknown operation sends error
3. handleStatus returns operation details
4. handleList returns all active operations

**SyncOpsHandler** — refactor `handleExecute()`:

1. **Add imports**: StreamingPipeline, ChunkedBulkExecutor, BackgroundOperationRegistry.
2. **Add `registry` to constructor** (injected via deps or as second constructor arg, matching ExecutionHandler pattern).
3. **Add streaming threshold constant**: `const STREAMING_THRESHOLD = 10_000;`.

4. **Refactor `handleExecute()`**:
   - Keep all the setup code (production guard, duplicate check, connection, performance tracking) — this runs synchronously before detaching.
   - Create an `AbortController` for this operation.
   - Build the orchestrator and all CRUD functions as before.
   - **New**: Create the execution promise as a separate `async` function:
     ```typescript
     const executionPromise = this.executeSync(
       config, orchestrator, operationId, bulkManager, progressTracker,
       sourceConn, targetConn, abortController.signal
     );
     ```
   - Register with BackgroundOperationRegistry:
     ```typescript
     this.registry.register(operationId, 'sync', `Sync ${config.objects?.length ?? 0} object(s)`, executionPromise, abortController);
     ```
   - Send `operation:started` and return immediately (no await).

5. **New private method `executeSync()`**: Extracts the current try/catch/finally body:
   - Calls `orchestrator.execute(config)`.
   - On success: update registry progress to 100%, send `operation:completed`, send result response.
   - On failure: send `operation:failed`.
   - In finally: cleanup (progressTracker, performanceTracker, dmlTracker, activeOperationIds).

6. **Streaming integration in CRUD functions**: For `insertFn`, `upsertFn`, `updateFn` — when `records.length > STREAMING_THRESHOLD`:
   - Create `ChunkedBulkExecutor` instead of `BulkApiExecutor.executeBulk()`.
   - Use `createChunkGenerator(records, 2000)` to chunk the records.
   - Pass `abortController.signal` for cancellation.
   - Map the `StreamingExecutionResult` back to the existing return format.

**Tests**:
- Existing tests should still pass (below-threshold path unchanged).
- New tests:
  1. handleExecute returns immediately without awaiting execution
  2. Operation registered in BackgroundOperationRegistry
  3. Large record set (>10K) uses ChunkedBulkExecutor
  4. Abort cancels running operation
  5. Cleanup runs in finally block even when detached

**extension.ts** — wire BackgroundOperationRegistry:

1. Import `BackgroundOperationRegistry`.
2. Create singleton in `activate()`:
   ```typescript
   const backgroundRegistry = new BackgroundOperationRegistry();
   ```
3. Subscribe to registry events for native notifications:
   ```typescript
   backgroundRegistry.onEvent((operationId, type, operation) => {
     if (type === 'completed' || type === 'failed') {
       // Update WebviewStateSync
       stateSync.setActiveOperations(backgroundRegistry.getActiveOperations());

       // Native notification if no panel visible
       if (!panelManager.isAnyPanelVisible() && !operation.notifiedNatively) {
         backgroundRegistry.markNotifiedNatively(operationId);
         const label = type === 'completed'
           ? `SandForge: ${operation.module} completed — ${operation.resultSummary ?? 'done'}`
           : `SandForge: ${operation.module} failed — ${operation.resultSummary ?? 'error'}`;
         vscode.window.showInformationMessage(label, 'Show Details').then((action) => {
           if (action === 'Show Details') {
             panelManager.openPanel({ viewType: 'sandforge-main', title: 'SandForge', column: 1 });
           }
         });
       }
     }
     if (type === 'started' || type === 'progress') {
       stateSync.setActiveOperations(backgroundRegistry.getActiveOperations());
     }
   });
   ```
4. Pass `backgroundRegistry` to handler constructors that need it (SyncOpsHandler, SeedOpsHandler, ExecutionHandler).
5. Add `backgroundRegistry.dispose()` to the deactivate disposables.
