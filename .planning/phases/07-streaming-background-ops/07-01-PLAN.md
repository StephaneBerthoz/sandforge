# Plan 01: Streaming Execution Engine

## Objective

Create the core streaming infrastructure: a `StreamingPipeline` that processes records in chunks using async generators (never holding more than one chunk in memory), and a `ChunkedBulkExecutor` that uploads records to a single Bulk API 2.0 job in multiple batches. These are low-level engine components that Plan 07-03 will wire into handlers.

## Context

- **Current state**: `BulkApiExecutor.executeBulk()` receives ALL records at once (`await job.uploadData(records)` — line 150). For 100K+ records this loads everything into memory.
- **Streaming goal**: Process records in 2000-record chunks. The async generator yields batches; the pipeline processes each batch and releases it.
- **Bulk API 2.0**: Supports multiple `uploadData()` calls to the same job before `close()`. This is more efficient than creating a job per chunk.
- **AbortController**: ForgeHandler already uses `AbortController` (lines 399-414). The streaming pipeline accepts an `AbortSignal` and checks it between chunks.
- **ObjectProgress**: Existing type in `execution.types.ts` (line 10-29). Add optional `chunksProcessed` and `totalChunks` for chunk-level granularity.

**StreamingPipeline** — new class:

```typescript
import type { StreamingChunkResult, StreamingExecutionResult } from '@sandforge/shared';

/** Progress callback for chunk completion. */
export type OnChunkProgress = (chunksProcessed: number, totalChunks: number, chunkResult: StreamingChunkResult) => void;

/** Function that processes a batch of records and returns a chunk result. */
export type ChunkProcessFn = (records: Record<string, unknown>[]) => Promise<StreamingChunkResult>;

/** Configuration for the streaming pipeline. */
export interface StreamingPipelineConfig {
  /** Abort signal for cancellation. */
  signal?: AbortSignal;
  /** Callback after each chunk completes. */
  onChunkProgress?: OnChunkProgress;
  /** Total number of chunks (for progress calculation, if known upfront). */
  totalChunks?: number;
}
```

**Class `StreamingPipeline`**:
- Constructor takes `StreamingPipelineConfig`.
- Method `async execute(chunks: AsyncIterable<Record<string, unknown>[]>, processFn: ChunkProcessFn): Promise<StreamingExecutionResult>`:
  1. Initialize aggregate counters: `totalRecords = 0, successCount = 0, failureCount = 0, successIds: string[] = [], errors: string[] = [], chunksProcessed = 0`.
  2. `for await (const chunk of chunks)`:
     a. Check `signal?.aborted` → if true, return result with `aborted: true`.
     b. Call `processFn(chunk)` → get `StreamingChunkResult`.
     c. Accumulate: `totalRecords += chunk.length`, `successCount += result.successCount`, `failureCount += result.failureCount`.
     d. Push `result.successIds` into aggregate (needed for reference linking in seed). Note: for sync mode where IDs aren't needed, pass empty arrays to save memory.
     e. Push `result.errors` into aggregate (capped at 100 to prevent memory growth).
     f. Increment `chunksProcessed`.
     g. Call `onChunkProgress?.(chunksProcessed, totalChunks ?? chunksProcessed, result)`.
  3. Return `StreamingExecutionResult` with `aborted: false`.

**Key design choices**:
- `successIds` accumulation is opt-in: callers that don't need IDs (sync) pass processFn that returns empty arrays. Callers that need IDs (seed with reference linking) pass the real IDs.
- Errors are capped at 100 entries to prevent memory growth on massive failures.
- The pipeline is stateless — create a new instance per execution.

**Tests**:
1. Processes all chunks from an async generator
2. Accumulates success/failure counts correctly
3. Calls onChunkProgress after each chunk with correct counts
4. Aborts when signal is triggered — returns aborted: true and stops processing
5. Handles empty chunks gracefully (skips them)
6. Caps errors at 100 entries

```typescript
import type { BulkApiConnection, BulkApiExecutorDeps, BulkOperation, BulkJobHandle } from './BulkApiExecutor.js';
import type { BulkApiManager } from './BulkApiManager.js';
import type { StreamingChunkResult } from '@sandforge/shared';

export interface ChunkedBulkConfig {
  /** Records per upload chunk (default 2000). */

  /** Polling interval in ms (default 5000). */
  pollIntervalMs: number;
  /** Abort signal for cancellation. */

}
```

**Class `ChunkedBulkExecutor`**:
- Constructor takes `ChunkedBulkConfig` with defaults `{ chunkSize: 2000, pollIntervalMs: 5000 }`.
- Method `async executeChunked(deps: BulkApiExecutorDeps, objectName: string, operation: BulkOperation, recordChunks: AsyncIterable<Record<string, unknown>[]>, totalRecords: number, externalIdField?: string): Promise<StreamingExecutionResult>`:
  1. Check `deps.bulkManager.canStartNewJob()` → throw if not.
  2. Create job via `deps.connection.bulk2.createJob(...)`.
  3. Register job with `deps.bulkManager.registerJob(...)`.
  4. `await job.open()`.
  5. Upload phase: `for await (const chunk of recordChunks)`:
     a. Check `signal?.aborted` → if true, close job, return aborted result.
     b. `await job.uploadData(chunk)`.
     c. Track `uploadedRecords += chunk.length`.
     d. Report upload progress via `deps.onProgress?.(uploadedRecords, totalRecords)`.
  6. `await job.close()`.
  7. Poll phase: `while` loop checking `job.check()` (same as existing BulkApiExecutor lines 154-158).
     a. Check `signal?.aborted` between polls.
     b. Update `bulkManager.updateJobState(...)`.
     c. Report processing progress via `deps.onProgress`.
  8. Get results: `await job.getAllResults()`.
  9. Parse into success IDs + failures (same as existing BulkApiExecutor lines 162-174).
  10. Update `bulkManager.updateJobCounts(...)`.
  11. Return `StreamingExecutionResult`.

- Method `createChunkGenerator(records: Record<string, unknown>[], chunkSize: number): AsyncGenerator<Record<string, unknown>[]>`:
  Static helper that wraps a flat array into an async generator yielding chunks. Used when callers have all records in memory but want to use the chunked API.
