# Plan 1: Quick Sync Backend — Smart Object Suggestions, Relationship Detection, Preview Estimator

## Objective

Build the three backend services that make Quick Sync "smart": (1) SmartObjectSuggester that recommends the top 5 most-used objects after org selection, (2) RelationshipDetector that analyzes describe metadata to auto-suggest parent objects when a child is added, and (3) QuickSyncPreviewEstimator that computes record counts and API call estimates before execution. Wire all three through a new QuickSyncHandler bridge handler that also delegates execution to the existing SyncOrchestrator with auto-generated config using smart defaults.

## Context

- **AutoFieldMapper already exists** at `packages/extension/src/modules/sync/AutoFieldMapper.ts` — Quick Sync will reuse it directly for QSYNC-03 (auto-match same-name fields). No changes needed to AutoFieldMapper.
- **SyncOrchestrator already exists** and handles full sync execution — Quick Sync builds a SyncConfig with smart defaults (QSYNC-04: direction=source_to_target, mode=full, conflict=source_wins, batchSize=200, operation=upsert) and delegates to it.
- **SyncOpsHandler** handles `sync:*` message types — Quick Sync uses separate `quicksync:*` message types via a new QuickSyncHandler.
- **Bridge pattern**: See `SyncOpsHandler.ts` for the pattern — implement `DomainHandler` interface, use `buildResponse`/`sendHandlerError` helpers, register in `MessageRouter.ts`.
- **Relationship detection**: Use jsforce `describe()` to find lookup/master-detail fields (`type === 'reference'`) with `referenceTo` array. When user adds "Opportunity", detect that it has `AccountId` (reference to Account) and suggest adding Account with lower insertOrder.
- **Smart object suggestions**: Hardcode the top 5 most common Salesforce objects (Account, Contact, Opportunity, Case, Lead) but filter against the org's actual available objects from `describeGlobal()`. Mark which ones the user has already selected.
- **Preview estimation**: For each selected object, query `SELECT COUNT() FROM ObjectName` to get record count. Estimate API calls as `ceil(recordCount / batchSize)` per object. Sum totals.
- **TypeScript strict, no `any`**, JSDoc on public methods, Winston logger (not console.log), i18n keys not needed in backend.

**RelationshipDetector** (SWIZ-06):

```typescript
interface DescribeFieldInfo {
  name: string;
  type: string;
  referenceTo: string[];
  relationshipName: string | null;
}

class RelationshipDetector {
  /**
   * Given a list of describe fields for an object, detect parent object dependencies.
   * Returns suggestions for parent objects that should be added to ensure referential integrity.
   */
  detect(
    childObjectApiName: string,
    childFields: DescribeFieldInfo[],
    alreadySelected: string[],
    availableObjects: string[],
  ): RelationshipSuggestion[]
}
```

- Scan fields where `type === 'reference'` and `referenceTo` contains a standard object name.
- Skip self-references (e.g., Account.ParentId -> Account if Account already selected).
- Skip already-selected objects.
- Skip non-available objects.
- Determine `relationshipType`: if field name ends with `Id` and the relationship is required (for now, heuristic: master-detail fields have names like `AccountId` on `Contact`), mark as `masterDetail`, otherwise `lookup`.
- Set `suggestedInsertOrder` to be lower than the child (parents inserted first).

```typescript
interface RecordCountResult {
  objectApiName: string;
  count: number;
}

class QuickSyncPreviewEstimator {
  /**
   * Estimate preview data for Quick Sync.
   * @param recordCounts - Record counts per object (from COUNT() queries)
   * @param batchSize - Batch size for API call estimation (default 200)
   */
  estimate(recordCounts: RecordCountResult[], batchSize?: number): QuickSyncPreview
}
```

- For each object: `estimatedApiCalls = Math.ceil(count / batchSize)`.
- `totalRecords = sum of all counts`.
- `totalApiCalls = sum of all estimatedApiCalls`.
- `estimatedDurationSec = totalApiCalls * 2` (rough estimate: 2 seconds per API call batch).

**QuickSyncHandler** (QSYNC-01 through QSYNC-06 bridge wiring):

Implement `DomainHandler` interface handling these message types:

- `quicksync:suggest-objects` — Payload: `{ orgId, alreadySelected }`. Calls `describeGlobal` to get available objects, runs `SmartObjectSuggester.suggest()`, returns suggestions.
- `quicksync:detect-relationships` — Payload: `{ orgId, objectApiName, alreadySelected, availableObjects }`. Calls `describe(objectApiName)` to get fields, runs `RelationshipDetector.detect()`, returns suggestions.
- `quicksync:preview` — Payload: `{ sourceOrgId, selectedObjects }`. Runs `SELECT COUNT() FROM X` for each object, feeds into `QuickSyncPreviewEstimator.estimate()`, returns preview.
- `quicksync:execute` — Payload: `{ config: QuickSyncConfig }`. Validates with Zod schema. Builds a full `SyncConfig` with smart defaults (QSYNC-04): `direction='source_to_target'`, `mode='full'`, `conflictStrategy='source_wins'`, `operation='upsert'`, `batchSize=200`. For each object, uses `AutoFieldMapper` to auto-generate field mappings (QSYNC-03) by calling describe on both source and target, then delegates to the existing sync execution flow (reuse the execution logic pattern from SyncOpsHandler.handleExecute).

Register `QuickSyncHandler` in `MessageRouter.ts` following the existing pattern for `SyncOpsHandler`.
