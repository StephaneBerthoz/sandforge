# Plan 2: Quick Sync Frontend — 3-Screen Flow UI, Preview, Results Integration

## Objective

Build the Quick Sync frontend: a prominent entry card on SyncPage that launches a streamlined 3-screen flow (pick orgs, pick objects, preview+go). The object step includes smart suggestions (top 5 chips) and relationship auto-detection toasts. The preview step shows estimated records and API calls. After execution, results reuse the existing Step6 results component. This delivers the "prod to sandbox in 3 clicks" promise.

## Context

- **Plan 03-01 delivers the backend**: `quicksync:suggest-objects`, `quicksync:detect-relationships`, `quicksync:preview`, `quicksync:execute` bridge messages. This plan consumes them via `useBridgeQuery` / `useBridgeMutation` hooks.
- **Existing bridge hooks**: `useBridgeQuery(type, payload, opts)` for read-on-mount, `useBridgeMutation(type, opts)` for on-demand calls. See `useSyncPageData.ts` for usage pattern.
- **Existing UI components**: `Select`, `Button`, `Card/CardHeader/CardBody`, `Badge`, `ProgressBar`, `PageHeader`, `OrgBadge`, `Wizard` — all in `packages/webview/src/components/ui/`.
- **SyncPage.tsx** currently renders `PageHeader` + `SyncWizard`. Quick Sync card goes between them. When Quick Sync is active, it replaces the wizard area with the QuickSyncFlow. A "Back to full wizard" link returns to the wizard.
- **Step6 results pattern**: The results rendering in SyncPage lines 395-432 uses `SyncExecutionResult` type with `objectResults` array. QuickSyncPreviewStep will receive the same result type after execution and render it identically.
- **i18n**: All visible text must use `t('quickSync.xxx')`. Add keys to both `en.json` and `fr.json`.
- **File naming**: PascalCase for components, camelCase for hooks. Tests in same folder.
- **Component pattern**: Functional React components with hooks, Tailwind CSS with VSCode CSS variables.
- **useOrgStore**: Access connected orgs via `useOrgStore((s) => s.orgs)`.

**useQuickSyncFlow hook** — Central state management for the Quick Sync flow:

```typescript
type QuickSyncStep = 'orgs' | 'objects' | 'preview' | 'executing' | 'results';

interface QuickSyncFlowState {
  step: QuickSyncStep;
  sourceOrgId: string;
  targetOrgId: string;
  selectedObjects: string[];
  parentObjects: string[];  // auto-detected via relationship detection
  preview: QuickSyncPreview | null;
  result: SyncExecutionResult | null;
  isExecuting: boolean;
  error: string | null;
}

function useQuickSyncFlow(): {
  state: QuickSyncFlowState;
  setSourceOrg: (orgId: string) => void;
  setTargetOrg: (orgId: string) => void;
  addObject: (apiName: string) => void;
  removeObject: (apiName: string) => void;
  addParentObject: (apiName: string) => void;
  goToObjects: () => void;
  goToPreview: () => void;
  execute: () => void;
  reset: () => void;
  canGoToObjects: boolean;
  canGoToPreview: boolean;
}
```

- `goToObjects` validates orgs are selected and different, moves to 'objects' step.
- `goToPreview` triggers `quicksync:preview` bridge mutation, moves to 'preview' step.
- `execute` triggers `quicksync:execute` bridge mutation with QuickSyncConfig, moves to 'executing', then 'results' on completion.
- `reset` clears all state back to initial.
- Use `useBridgeMutation` for preview and execute calls.
- Use `useWebviewPersistedState` to persist draft state (org IDs, selected objects) across refreshes.
