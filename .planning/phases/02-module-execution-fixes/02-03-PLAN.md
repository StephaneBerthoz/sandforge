# Plan 03: Missing Handlers — Compare, Automation, Autopilot

## Objective

Implement the 6 missing handler methods that have UI consumers but no backend logic, plus add Autopilot node-progress messages during execution. These are real implementations using Salesforce APIs and ConfigStore, not stubs.

## Context

- Compare: 3 lazy-loaded tabs (permissions, snapshots, drift) have useBridgeQuery hooks but no handlers
- Automation: 3 queries (pipeline:list, pipeline:templates, pipeline:history) have hooks but no handlers
- Autopilot: no per-node progress messages sent during execution (UI shows empty progress)
- All handlers were migrated to buildResponse in Plan 01 — new methods follow the same pattern
- Depends on Plan 01 because it modifies the same handler files

Add progress messages during execution:

1. Before processing each node:
   ```typescript
   this.deps.broker.postToWebview(buildResponse(this.deps, msg, 'autopilot:node-progress', {
     nodeId: node.id,
     objectName: node.objectName,
     status: 'processing',
     wave: currentWave,
   }));
   ```

2. After each node completes:
   ```typescript
   this.deps.broker.postToWebview(buildResponse(this.deps, msg, 'autopilot:node-progress', {
     nodeId: node.id,
     objectName: node.objectName,
     status: 'completed',
     recordCount: result.successCount,
     failureCount: result.failureCount,
     wave: currentWave,
   }));
   ```

3. On node failure:
   ```typescript
   this.deps.broker.postToWebview(buildResponse(this.deps, msg, 'autopilot:node-progress', {
     nodeId: node.id,
     objectName: node.objectName,
     status: 'failed',
     error: extractErrorMessage(err),
     wave: currentWave,
   }));
   ```

Ensure the webview AutopilotPage.tsx already has a `useMessageListener('autopilot:node-progress', ...)` from Phase 1. If not, add one that updates the AutopilotStore graph nodes.
