# Plan 04: AI Conversation Persistence & API Key Guidance

## Objective

Implement AI-02 (conversation persistence) and AI-03 (API key guidance). Conversations are stored in ConfigStore with per-conversation keys to avoid size limits. When AI is not configured, AIPage shows helpful guidance instead of an empty chat.

## Context

- AIChatHandler already handles: `ai:chat`, `ai:conversation:create`, `ai:conversation:list`, `ai:conversation:delete`, `ai:status`, `ai:save-key`
- ConfigStore is injected via `deps.configStore` in all handlers
- Research Pitfall 6: use per-conversation keys (`ai:conversation:{id}`) with a separate index key
- `useAppStore.aiAvailable` is already set on mount via `ai:status` (Phase 1 fix)
- i18n required for all user-visible strings

<action>
Read AIChatHandler.ts fully. Understand current conversation handling (likely in-memory).

Add ConfigStore persistence:

1. **Index key:** `ai:conversations:index` — stores array of `{ id, title, createdAt, messageCount }`
2. **Conversation key:** `ai:conversation:{id}` — stores full conversation with messages
3. **Category:** `'ai'` for all AI keys (enables `getByCategory('ai')`)

Implement persistence in existing handler methods:

- `ai:conversation:create` → create in ConfigStore + update index
- `ai:chat` → after processing, save updated conversation to ConfigStore
- `ai:conversation:list` → read from ConfigStore index (not in-memory)
- `ai:conversation:delete` → remove from ConfigStore + update index
- Add `ai:conversation:load` handler → load specific conversation by id from ConfigStore

Message cap: limit to 200 messages per conversation. When exceeded, prune oldest messages (keep system message + last 200).

All responses must use `buildResponse()` with correlationId.
