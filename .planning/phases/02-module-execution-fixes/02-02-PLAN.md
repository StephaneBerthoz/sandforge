# Plan 02: ForgeHandler DomainHandler Refactor

## Objective

Rewrite ForgeHandler from the old `handle(type, payload)` pattern to the standard DomainHandler interface. Replace raw `postMessage()` with `broker.postToWebview()`, use `buildResponse()` for all responses, and migrate in-memory templates/history to ConfigStore.

## Context

- ForgeHandler is the only handler using the old pattern (`ForgeHandlerDeps` with raw `postMessage`)
- ForgeOpsHandler wraps it as a DomainHandler but strips BaseMessage before delegation (breaks correlationId)
- Templates and history are in-memory arrays (lost on extension reload)
- Research Pitfall 2: the delegation chain strips BaseMessage, making buildResponse impossible
- Research Pitfall 8: in-memory storage is unreliable for real-world usage
- All other handlers follow: type set → `handle(msg)` → switch → private methods → `buildResponse()`
