# Plan 02-03: Playwright E2E — 5 Critical User Flows

**Requirements covered:** TEST-03 (Playwright E2E critical paths: 5 flows — seed AI persona then execute, quick sync with conflict then resolve, monitor dashboard refresh then export, CDC subscription then event received, AI diagnose failed job then apply fix).

**Goal:** Extend the existing `packages/webview/e2e/` Playwright suite with 5 new spec files covering the 5 critical user flows mandated by D-02-4. Each spec uses `MockBridge` + `injectVSCodeApiMock` (already present in repo) to script extension-side responses — no real VSCode extension host required. Reuse existing fixture helpers. If a target component lacks a stable `data-testid`, add one as part of this plan. All specs must be deterministic and green in CI with 2 retries (`playwright.config.ts` already sets `retries: 2` for CI — no config edit).

**Depends on:** Plan 02-01 (Stryker) and Plan 02-02 (fast-check) — running in Wave 2 avoids any concurrent edit risk on shared tooling and lets Wave 1 stabilize dep changes in the lockfile. File-overlap: none with 02-01 / 02-02 (Playwright files live exclusively in `packages/webview/e2e/`; MockBridge extensions here do not collide with any other plan's writes).

**Non-goals:** Running Playwright against the real VSCode extension host (deferred to v1.4 nightly per D-02-4). Adding new fixture types beyond what the 5 specs need. Re-running Stryker on webview (explicitly excluded per D-02-1). Visual-regression testing (explicitly out of scope per CONTEXT non-goals). Adding a new Playwright config file.

### Task 02-03-01: Extend MockBridge with stream helper
<task>
<file>packages/webview/e2e/helpers/MockBridge.ts</file>
<action>Add one new additive method to the `MockBridge` class named `stream(messages, options?)`. It iterates an array of `{ type, payload }` entries and, for each, calls `page.evaluate` to dispatch a `MessageEvent` on `window` with `data: { type, id: 'resp-<timestamp>-<rand>', payload }` and `origin: ''`. Optional `options.delayMs` inserts a `page.waitForTimeout(delayMs)` between messages. No changes to existing methods. JSDoc: "Post a sequence of messages from the extension to the webview with an optional delay between them. Useful for simulating CDC event streams or multi-step extension responses."</action>
<verify>`pnpm --filter @sandforge/webview typecheck` succeeds. Run one existing spec (`pnpm --filter @sandforge/webview e2e -- seed.spec.ts`) to confirm no regression from the additive change.</verify>
<done>`stream` method added; existing specs unaffected; new method typechecks.</done>
</task>
