# Plan 03: Alert History UI + Governance Panel Bridge Wiring

## Objective

Complete the webview-side wiring for alerts and governance. This plan creates the AlertHistoryPanel (ALERT-05) showing a timeline of all alert events (triggered/acknowledged/resolved/dismissed), and wires the existing GovernancePanel to live bridge queries so it can display real policies, run evaluations, and show compliance results. Depends on Plans 01 and 02 which provide the backend handlers.

## Context

- Plan 01 added `monitor:alerts` handler that responds with `{ alerts: AlertInstance[], history: AlertInstance[] }`. The `history` array contains ALL alerts (active + resolved + dismissed) for the timeline.
- Plan 02 added `GovernanceOpsHandler` that handles `governance:policies:list`, `governance:evaluate`, `governance:policy:delete`, `governance:templates`, etc.
- `AlertsPanel.tsx` already works for active alerts with ack/dismiss buttons. It queries `monitor:alerts` with response type `monitor:alerts:result`. This panel is already functional after Plan 01.
- `GovernancePanel.tsx` exists as a pure presentational component. It receives props (`policies`, `ruleResults`, `complianceScore`, etc.) but has no bridge query wiring. It needs a wrapper or hook that connects it to the bridge.
- `MonitorPage.tsx` renders `AlertsPanel` in the bottom row alongside `PredictionsTile`. The new `AlertHistoryPanel` should be added as a separate section.
- The webview uses `useBridgeQuery` and `useBridgeMutation` hooks for bridge communication.
- i18n: all visible text must use `t('key')` from react-i18next.
- Alert timeline should group alerts by date, show status changes with timestamps, and use color-coded status badges.

4. `useBridgeMutation<{ success: boolean }>('governance:policy:save', { responseType: 'governance:policy:save:response' })` -- for adding from templates.
