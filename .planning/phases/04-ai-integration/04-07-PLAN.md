# Plan 04-07: Multi-provider stubs + legacy AI module migration + per-provider isolation proof

**Requirements covered:** AI-01 multi-provider portion (factory ships all 3 providers from day one with stubs for non-Anthropic), AI-04 RT-#11 closure (Zod-validated structured output replaces regex extract across the entire codebase, not just new flows).

## Goal

Close out Phase 04 with the polish work that cements the architecture. The `AIClientFactory` from 04-01 currently throws `AINotImplementedError` directly at factory time for non-Anthropic providers — this means a user accidentally setting `sandforge.ai.provider: 'openai'` in Settings would crash any handler that calls `services.aiClient()`. This plan ships proper stub adapters that satisfy the interface and only throw at method-call time, so the factory dispatch is safe. The three legacy AI modules that still use the regex-extract JSON pattern (`AIAssistant`, `ErrorResolver`, `NL2SOQL`) are migrated to `aiClient.complete(schema)`, closing RT-#11 fully across the codebase. A per-provider breaker isolation integration test proves the CONTEXT lock holds.

## Context

CONTEXT decisions locked: factory + 1 adapter per provider; per-provider breaker so a 529 storm on Anthropic does NOT degrade OpenAI / Custom; explicit "factory ships with all 3 providers from day one" (RESEARCH §"Deferred Ideas" — `OpenAIAdapter + CustomAdapter as thin scaffolds with NotImplementedError if the adapter isn't ready"`). RESEARCH §"Existing Patterns" mandates that `AIAssistant`, `ErrorResolver`, `NL2SOQL`, `AIPersonaManager`, `SchemaAdvisor`, `SmartActionAnalyzer`, `AnomalyDetector`, `PipelineGenerator` keep their PUBLIC APIs intact while their internal `provider(prompt)` callsite migrates to the new `AIClient`.

This plan migrates the 3 highest-traffic legacy modules (`AIAssistant`, `ErrorResolver`, `NL2SOQL`). The remaining 5 modules (`AIPersonaManager`, `SchemaAdvisor`, `SmartActionAnalyzer`, `AnomalyDetector`, `PipelineGenerator`) keep their existing wiring for now — migrating all 8 in one plan would explode scope and risk. They are tracked as a `v1.4` follow-up (added to STATE.md backlog by the verify-phase agent).

The integration test in this plan proves the lock that's hardest to verify by inspection: that the per-provider breaker on AnthropicAdapter does NOT bleed into the OpenAIAdapter / CustomAdapter instances. Without this test, a future refactor that accidentally elevates the breaker to a global singleton would silently violate the CONTEXT decision.

## Pitfalls mitigated (RESEARCH §"Common Pitfalls")

- **RT-#11 (regex-extract JSON instead of Zod-validated structured output)** — fully closed across `AIAssistant`, `ErrorResolver`, `NL2SOQL`.
