# Plan 04-03: Read-only tool surface + toolRunner + tool-trace streaming

**Requirements covered:** AI-04 (tool surface, defense in depth, Zod validation of every tool I/O), AI-02 partial (the diagnose flow in Plan 04-04 consumes this tool surface).

## Goal

Ship the canonical fine-grained, strictly-read-only tool surface that Claude orchestrates. Every tool is named with a read verb, validates input AND output through Zod, returns a `{ ok: true, data } | { ok: false, error: { code, message, hint } }` discriminated union, and emits a `ai:tool-trace` bridge event per call so the chat panel can render a live "1/4 describe_object Account... 2/4 query_records..." trace. A vertical-slice test proves a 2-step flow ("describe Account, then count its records") works end to end through `client.beta.messages.toolRunner` with the for-await stream.

## Context

CONTEXT decisions locked: fine-grained ~10-15 tools, one per SF API, strictly read-only, mutations NEVER as tool calls, Zod-validated payload (success AND error). RESEARCH §"Don't Hand-Roll" confirms `betaZodTool` + `client.beta.messages.toolRunner`. Pitfall #4 mandates a CI-enforceable name regex fence so future PRs cannot smuggle a `apply_*` / `delete_*` / `update_*` / `deploy_*` tool. Pitfall #8 mandates the wrapTool helper because `betaZodTool` validates INPUT only — output is verbatim. Pitfall #10 mandates the for-await streaming pattern so the user sees a live trace.

Each tool is defined as a single file under `adapters/ai/tools/`. The file exports a builder function that takes the services it needs (`services.salesforce`, `services.monitor`, etc.) and returns a `BetaZodTool` definition. Tools that need Salesforce go through `ConnectionPool` (RESEARCH §"Existing Patterns") — NEVER `new jsforce.Connection()`. Tools that read Monitor data go through `monitorOrchestrator.timeSeriesStore.query()` and `monitorOrchestrator.alertEngine.listInstances()` (read-only methods only — never `record` / `clear` / `submit`).

This plan does NOT yet wire the diagnose flow handler — that's Plan 04-04. This plan only ships the tool surface, the toolRunner integration, and a vertical-slice integration test calling `runTools()` directly with a synthetic prompt.

## Pitfalls mitigated (RESEARCH §"Common Pitfalls")

- **P-04.4 (Mutations sneak in as tools)** — naming convention + CI-enforceable regex fence.
- **P-04.8 (Tool errors lost as raw strings to Claude)** — `wrapTool` enforces `ToolResultSchema` discriminated-union output.
- **P-04.10 (60s webview "frozen" UX)** — `for await` streaming over toolRunner emits `ai:tool-trace` events per step.

   import { betaZodTool } from '@anthropic-ai/sdk/helpers/beta/zod';
   import { z } from 'zod';
   import { toolResultSchema, type ToolError } from '@sandforge/shared';

   export interface WrapToolOptions<I extends z.ZodObject<any>, O extends z.ZodTypeAny> {
     name: string;
     description: string;
     input: I;
     output: O;                                        // for output validation BEFORE returning to Claude
     onTrace?: (event: { name: string; status: 'start'|'success'|'error'; durationMs?: number; errorCode?: string }) => void;
     run: (args: z.infer<I>, ctx: { signal: AbortSignal }) => Promise<z.infer<O>>;
   }

   const READ_ONLY_NAME_REGEX = /^(describe|query|get|list|count|validate|analyse|preview|fetch|read)_[a-z][a-z0-9_]*$/;

   export function wrapTool<I extends z.ZodObject<any>, O extends z.ZodTypeAny>(opts: WrapToolOptions<I, O>) {
     if (!READ_ONLY_NAME_REGEX.test(opts.name)) {
       throw new Error(`Tool name "${opts.name}" violates read-only convention. Allowed verbs: describe|query|get|list|count|validate|analyse|preview|fetch|read.`);
     }
     const Result = toolResultSchema(opts.output);
     return betaZodTool({
       name: opts.name,
       description: opts.description,
       inputSchema: opts.input,
       run: async (input, runCtx) => {
         const startedAt = Date.now();
         opts.onTrace?.({ name: opts.name, status: 'start' });
         try {
           const data = await opts.run(input, { signal: runCtx.signal });
           const result = Result.parse({ ok: true, data });
           const durationMs = Date.now() - startedAt;
           opts.onTrace?.({ name: opts.name, status: 'success', durationMs });
           return JSON.stringify(result);
         } catch (err) {
           const durationMs = Date.now() - startedAt;
           const code = err instanceof z.ZodError ? 'OUTPUT_SCHEMA_MISMATCH' : (err as Error & { code?: string }).code ?? 'TOOL_ERROR';
           const message = (err as Error).message ?? String(err);
           const error: ToolError = { code, message: message.slice(0, 2000) };
           opts.onTrace?.({ name: opts.name, status: 'error', durationMs, errorCode: code });
           const result = Result.parse({ ok: false, error });
           return JSON.stringify(result);
         }
       },
     });
   }

   export { READ_ONLY_NAME_REGEX };
   ```

public async runTools<T>(opts: {
  prompt: string;
  system?: string;
  tools: BetaZodTool[];
  signal?: AbortSignal;
  onTrace?: (event: { runId: string; toolName: string; status: 'start'|'success'|'error'; durationMs?: number; errorCode?: string }) => void;
  maxTokens?: number;
  maxIterations?: number;           // default 12 — caps multi-step loops
}): Promise<{ text: string; usage: AIUsage; model: string; stopReason: string | null; runId: string; toolCalls: number }> {
  const runId = crypto.randomUUID();
  return this.runWithBreaker('runTools', async (signal) => {
    const client = await this.getClient();
    const runner = client.beta.messages.toolRunner({
      model: this.model,
      max_tokens: opts.maxTokens ?? 4096,
      system: opts.system,
      messages: [{ role: 'user', content: opts.prompt }],
      tools: opts.tools,
      max_iterations: opts.maxIterations ?? 12,
    });
    runner.setRequestOptions({ signal });

    let toolCalls = 0;
    let lastUsage: AIUsage = { input: 0, output: 0, cacheRead: 0, cacheCreate: 0, total: 0 };
    let lastModel = this.model;
    let lastStopReason: string | null = null;

    // Stream per-step (Pitfall #10) — emits tool-trace events as the runner progresses
    for await (const message of runner) {
      // The runner yields each assistant message (incl tool_use blocks).
      // Tool-trace start/success/error fires from inside wrapTool (already wired via opts.onTrace); we count here.
      if (message.content?.some((b: any) => b.type === 'tool_use')) toolCalls++;
      if (message.usage) lastUsage = this.buildUsage(message.usage);
      if (message.model) lastModel = message.model;
      if (message.stop_reason) lastStopReason = message.stop_reason;
    }

    const finalMessage = await runner.finalMessage();
    const text = finalMessage.content.filter((b: any) => b.type === 'text').map((b: any) => b.text).join('');

    return { text, usage: lastUsage, model: lastModel, stopReason: lastStopReason, runId, toolCalls };
  }, opts.signal);
}
```

`onTrace` is forwarded INTO each `wrapTool({ ..., onTrace: (e) => opts.onTrace?.({ runId, ...e }) })` build — so tool-internal events pick up the runId.
