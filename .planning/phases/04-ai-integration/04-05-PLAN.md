# Plan 04-05: Token budget per panel-session + soft 80% / hard 100% UX

**Requirements covered:** AI-04 token-budget portion (per-session counter, soft 80% / hard refuse 100%, Settings deeplink).

## Goal

Cap AI cost per panel-session with honest accounting. The user sees a live status-bar indicator from the moment they open the AI panel; at 80% they get a one-shot toast warning; at 100% the next request is refused via a modal that links straight to Settings. Counting includes ALL four token fields (input + output + cacheRead + cacheCreate) — Pitfall #6 explicitly: output-only counters under-bill 5-20×. Pre-flight token counting via `client.beta.messages.countTokens` ensures we refuse cleanly BEFORE making the HTTP call when the predicted input would push over budget.

## Context

CONTEXT decisions locked: budget is per panel-session (counter accumulates while AI panel open, resets on close), surfaces in status bar via `TokenUsageStats` interface, soft 80% toast / hard 100% modal with deeplink. RESEARCH §"Don't Hand-Roll" confirms `client.beta.messages.countTokens` for pre-flight. RESEARCH Pitfall #6: counter MUST sum input + output + cacheRead + cacheCreate. Existing setting `sandforge.ai.tokenBudgetMaxPerSession` does NOT exist yet — this plan adds it (default 50_000 tokens per CONTEXT specifics).

The `SessionBudget` is a singleton scoped to the active AI panel session. Plan 04-01 added `services.aiClient(provider?)` as a memoised factory; this plan does NOT memoise the budget at the same scope (the budget belongs to the panel, not the adapter — opening / closing the panel resets it). Instead, the AI panel's bridge handler creates a fresh `SessionBudget` on panel-open and disposes it on close, then injects it into the `AIDiagnoseHandler` (and any future handler that calls `aiClient.runTools`). Each adapter call increments the budget AFTER receiving the response.

## Pitfalls mitigated (RESEARCH §"Common Pitfalls")

- **P-04.6 (Output-only counter under-bills)** — `SessionBudget` sums all four `AIUsage` fields.
- **Pre-flight refusal** — `preflight(predictedInput)` uses `countTokens` BEFORE the HTTP call so a 100%-budget user gets a clean rejection, not a "AI replied with 0 tokens" error.

1. Create `packages/extension/src/adapters/ai/tokenBudget/SessionBudget.ts`. Export `class SessionBudget`. Constructor: `({ sessionId: string, budget: number, broker?: MessageBroker, telemetry?: TelemetryAdapter })`.

   Internal state:
   - `private used: AIUsage = { input: 0, output: 0, cacheRead: 0, cacheCreate: 0, total: 0 }`.
   - `private warnFired = false` — debounce flag.

   Public API:
   - `increment(usage: AIUsage): TokenBudgetState` — additive sum on all four fields, recomputes total. Recomputes `percent = (used.total / budget) * 100`. Sends `ai:budget:state` envelope every call. If `percent >= 80 && !warnFired`: set `warnFired = true`, send `ai:budget:warn`. If `percent >= 100`: send `ai:budget:exceeded` (every breach call). Returns the new state.
   - `preflight(predictedInput: number): { allowed: boolean; state: TokenBudgetState }` — computes `projectedTotal = used.total + predictedInput`. If `projectedTotal > budget`, returns `{ allowed: false, state: { ..., percent: clamped<=200, state: 'exceeded' } }` AND sends `ai:budget:exceeded`. Otherwise `{ allowed: true, state: getState() }`.
   - `reset(): void` — zero all fields, clear `warnFired`, send `ai:budget:state` with state `'ok'`.
   - `getState(): TokenBudgetState` — pure read of current state.
   - `dispose(): void` — alias for reset.

   The `state` discriminator:
   - `percent < 80` → `'ok'`
   - `80 <= percent < 100` → `'warn'`
   - `percent >= 100` → `'exceeded'`

   Edge cases:
   - `budget <= 0` at construction → throw `Error('Token budget must be positive')`.
   - `usage.total = NaN` in `increment` → coerce to 0, log a warn (defensive).
   - Race: `percent` capped at 200 in the schema.

2. Create `packages/extension/src/adapters/ai/tokenBudget/index.ts` barrel exporting `SessionBudget`.

3. Create `packages/extension/src/adapters/ai/tokenBudget/SessionBudget.test.ts`. Required tests (>= 11):
   - **Initial state** — new SessionBudget(`{ sessionId:'s1', budget: 1000 }`); `getState()` returns `{ used: zeros, percent: 0, state: 'ok' }`.
   - **Increment sums all 4 fields** — increment `{ input:10, output:5, cacheRead:3, cacheCreate:2, total:20 }`; used.total === 20; subsequent increment `{ input:5, output:5, cacheRead:0, cacheCreate:0, total:10 }` → used.total === 30, used.input === 15.
   - **State transition: ok -> warn -> exceeded** — budget 100; increment 50 → `'ok'`; increment 35 (total 85) → `'warn'`; increment 30 (total 115) → `'exceeded'`.
   - **Warn fires once** — three increments crossing 80%, then more increments above 80%. `ai:budget:warn` envelope sent EXACTLY ONCE (broker.send spy filtered by type).
   - **Exceeded fires every call once over** — over the 100% line, every additional `increment` AND every failed `preflight` sends `ai:budget:exceeded` (warn does NOT re-fire).
   - **Preflight refuses when projectedTotal > budget** — budget 100, used.total=80; preflight(25) → `{ allowed: false, state: { state: 'exceeded' } }`. `ai:budget:exceeded` sent.
   - **Preflight allows when projectedTotal <= budget** — budget 100, used.total=80; preflight(15) → `{ allowed: true }` (95 still under 100). NO exceeded envelope.
   - **Reset clears state** — increment to 90; reset; `getState() === { used: zeros, percent: 0, state: 'ok' }`. `warnFired` cleared (next 80% crossing fires warn again).
   - **Budget=0 throws at construction**.
   - **NaN guard** — `increment({ ...nans... })` does NOT crash; logs warn; state unchanged or coerced to 0.
   - **ai:budget:state fires on every increment** — 5 increments → 5 `ai:budget:state` envelopes (UI mini-bar live update).
