# Plan 06-01: Onboarding & First-Run Sandbox Guidance

## Objective

Implement 4 onboarding requirements (ONBO-01 through ONBO-04) that create a cohesive first-run experience for sandbox users. The plan adds sandbox detection logic, a reusable contextual banner, updates the Welcome wizard's Step 4 to suggest Seed/Sync instead of Forge, adds a "Populate Sandbox" quick action on the Home dashboard, and adds guided first-step cards on SyncPage and SeedPage when no configs/templates exist. This is the final phase of v1.2.2, wiring Quick Sync (Phase 03) and Quick Seed (Phase 04) into the onboarding funnel.

## Context

**Org type detection:** `SalesforceOrg.orgType` is typed as `'Production' | 'Sandbox' | 'Scratch' | 'Developer'` in `packages/shared/src/types/org.types.ts`. The `useOrgStore` exposes `orgs` array with this field. Sandbox detection is purely client-side: check if any connected org has `orgType === 'Sandbox'`.

**Welcome wizard (WelcomePage.tsx):** 5-step wizard. Step 4 currently shows "Open Forge" for sandbox orgs and "Open Monitor" for production. The `orgType` prop defaults to `'sandbox'`. The requirement is to change the sandbox branch to show Seed + Sync buttons instead of Forge. Existing i18n keys include `onboarding.suggestSeed` and `onboarding.openSeed`.

**HomePage.tsx:** Bento grid layout with KPI row, Forge hero tile, health tile, recent ops tile, and quick actions tile (2x2 grid of buttons). The "Populate Sandbox" card should be added to the quick actions grid. The sandbox banner (ONBO-01) should appear above the bento grid when a sandbox org is detected.

**SyncPage.tsx:** Already imports and renders `QuickSyncCard` and `QuickSyncFlow`. When `orgs.length < 2`, it shows an EmptyState. The guided card should appear when the user has orgs but hasn't started anything yet (above QuickSyncCard).

**SeedPage.tsx:** Already imports and renders `TemplateGallery` and `QuickSeedFlow`. When `orgs.length === 0`, it shows an EmptyState. The guided card should appear on step 0 above the TemplateGallery as an intro/orientation card.

**i18n:** All new text must be added to `en.json` and `fr.json` under an `onboarding` or relevant namespace. Existing onboarding keys are in `en.json` lines 1036-1066.

**Project rules:** TypeScript strict, no `any`, every `.ts` gets a `.test.ts`, JSDoc on public interfaces, i18n for all visible text, Zod not needed here (no external data). Follow the work loop: create file, create test, typecheck, lint, test, build.
