# Plan 01: CorrelationId Infrastructure

## Objective

Add correlationId support to the message bridge for reliable request/response matching. Currently `useMessageResponse` matches by `type` only, which can collide if two queries of the same type are in flight. This plan adds correlationId to BaseMessage, propagates it through the extension, and updates the webview hooks to match on it.

## Context

- `BaseMessage` in `packages/shared/src/types/messages.types.ts` already has `id` field
- `buildMessage()` in `messageHelpers.ts` generates unique `id` per message (`wv-${Date.now()}-${++counter}`)
- `useMessageResponse.ts` line 114 matches by `eventData.type !== responseType` only
- Extension's `MessageBroker.ts` routes messages to handlers — needs to pass correlationId through
- Each handler in `packages/extension/src/bridge/handlers/*.ts` builds response messages — they need to copy correlationId from the incoming request
