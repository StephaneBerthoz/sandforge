# Plan 03: Ghost Type Cleanup & Unhandled Message Warning

## Objective

Clean messages.types.ts of ghost types (defined but never handled) and add development-mode warning logging for unhandled messages. This reduces confusion about what's actually implemented vs aspirational.

## Context

- messages.types.ts defines 130+ message types
- Several entire domains have types but zero handlers: audit:*, governance:*, scheduler:*, team:*, realtime:*
- Some of these have UI consumers (RealTimeSyncPanel.tsx) — those need careful handling
- Plan 02 will identify which handlers actually exist vs which are ghost

<name>Audit messages.types.ts for ghost types</name>
<files>
- packages/shared/src/types/messages.types.ts
</files>
<action>
Read messages.types.ts fully. For each message type definition:

1. Check if an extension handler exists (grep handlers/ directory)
2. Check if a webview consumer exists (grep pages/ and hooks/ directories)
3. Categorize:
   - ACTIVE: handler + consumer both exist
   - HANDLER-ONLY: handler exists, no UI consumer (keep, it's backend logic)
   - CONSUMER-ONLY: UI consumer exists, no handler (keep type, note missing handler)
   - GHOST: neither handler nor consumer (remove)

Build a complete categorization list before making any changes.

This helps future debugging — if a module sends a message and nothing happens, the Output panel shows why.
