# Plan 02: CDC Subscription UI & Live Event Feed

## Objective

Build the WebView UI for CDC real-time sync: a subscription panel where users select objects and start/stop the stream, a live event feed with virtual scrolling showing events in real-time, auto-sync toggle per object with conflict strategy, and the extension-side message handler that wires it all together. This replaces the "Coming Soon" placeholder in RealTimeSyncPanel with a fully functional CDC UI.

## Context

**Phase 01 deliverables available:**
- `VirtualList` component at `packages/webview/src/components/ui/VirtualList.tsx` -- use for the event feed
- `@tanstack/react-virtual` is installed

**Phase 02 deliverables available:**
- `SyncHistoryStore` pattern -- follow for useCDCLiveStore
- Message protocol patterns (`sync:history:*`, `sync:schedule:*`) -- follow for `realtime:*` messages

**Existing code:**
- `RealTimeSyncPanel.tsx` currently renders a "Coming Soon" badge with disabled controls. Replace entirely with functional UI.
- `SyncPage.tsx` has tabs: sync, history, schedules. Add a `realtime` tab.
- `messages.types.ts` already has `realtime:start`, `realtime:stop`, `realtime:status`, `realtime:metrics`, `realtime:event`, `realtime:events-batch` (added in Plan 01).
- `RealTimeSyncOrchestrator` (hardened in Plan 01) provides `onStatusChange`, `onEventFeed`, `getMetrics`, `start(config)`, `stop()`.

**Patterns to follow:**
- Zustand store pattern from `useSyncHistoryStore.ts` and `useSyncScheduleStore.ts`
- Message handler pattern: create a class that registers MessageBroker handlers for `realtime:*` messages
- Ring buffer on WebView side for event feed (5000 event capacity)
- All user-visible text uses `t('key')` via react-i18next
- Tests co-located in same directory

**Key design decisions:**
- The event feed uses a ring buffer (fixed array, not growing array) to prevent memory issues during high-throughput CDC
- VirtualList from Phase 01 handles the virtual scrolling rendering
- Auto-sync is per-object: each watched object can independently be set to auto-apply or monitor-only
- Conflict strategy selector appears per-object when auto-sync is enabled

<action>
1. Create `useCDCLiveStore.ts` Zustand store with the following state:
   - `status: 'disconnected' | 'connecting' | 'syncing' | 'paused' | 'error'` -- connection status
   - `watchedObjects: string[]` -- currently selected objects
   - `autoSyncObjects: Record<string, { enabled: boolean; conflictStrategy: ConflictStrategy }>` -- per-object auto-sync config
   - `events: CDCFeedEvent[]` -- ring buffer contents (visible window into the ring buffer)
   - `eventCount: number` -- total events received (may exceed buffer capacity)
   - `sourceOrgId: string | null`
   - `targetOrgId: string | null`

2. CDCFeedEvent type (define in the store file or a local types file):
   ```typescript
   interface CDCFeedEvent {
     replayId: number;
     objectApiName: string;
     changeType: string;
     recordIds: string[];
     commitTimestamp: string;
     changedFields: Record<string, unknown>;
     commitUser: string;
     applied: boolean;
     error?: string;
   }
   ```

3. Ring buffer implementation:
   - Private internal array of capacity 5000, write index, count
   - `pushEvents(batch: CDCFeedEvent[])`: append batch to ring buffer, update events getter to return ordered array from ring buffer
   - The `events` state field always returns the ring buffer contents in chronological order (oldest to newest)

4. Actions:
   - `setStatus(status)` -- update connection status
   - `setWatchedObjects(objects: string[])` -- update selected objects
   - `toggleAutoSync(objectName: string)` -- toggle auto-sync for an object
   - `setConflictStrategy(objectName: string, strategy: ConflictStrategy)` -- set per-object strategy
   - `pushEvents(batch: CDCFeedEvent[])` -- add batch to ring buffer
   - `clearEvents()` -- reset ring buffer
   - `setOrgs(sourceOrgId: string, targetOrgId: string)` -- set org pair
   - `reset()` -- full reset

5. Message listener: in the store, subscribe to `realtime:events-batch`, `realtime:started`, `realtime:stopped`, `realtime:status:response` messages from the extension using `window.addEventListener('message', ...)`. On `realtime:events-batch`, call `pushEvents`. On status messages, call `setStatus`.

6. Post actions: `startStream()`, `stopStream()` -- post `realtime:start` / `realtime:stop` messages to the extension via `getVscodeApi().postMessage(...)`.

7. Tests (useCDCLiveStore.test.ts):
   - Test ring buffer: push 6000 events, verify only last 5000 are retained in order
   - Test pushEvents with batch of events
   - Test toggleAutoSync creates entry with default strategy
   - Test setConflictStrategy updates existing entry
   - Test clearEvents resets buffer
   - Test startStream posts correct message
   - Test setStatus updates status field
</action>
