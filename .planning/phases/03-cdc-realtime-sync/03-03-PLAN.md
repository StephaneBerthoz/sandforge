# Plan 03: CDC Metrics Dashboard

## Objective

Build the CDC metrics dashboard that displays real-time throughput, replication lag, event counters, and uptime for the active CDC session. This provides observability into the CDC pipeline health. The dashboard polls metrics from the extension every 5 seconds and maintains a short history for sparkline visualizations.

## Context

**Backend support (from Plan 01):**
- `RealTimeSyncOrchestrator.getMetrics()` returns `RealTimeSyncMetrics` with: eventsReceived, eventsApplied, eventsFailed, eventsPerMinute, averageLagMs, currentLagMs, errorRate, startedAt, lastEventAt.
- `realtime:metrics` request and `realtime:metrics:response` response message types exist in messages.types.ts.
- The `RealTimeSyncMessageHandler` (from Plan 02) handles `realtime:metrics` and responds with metrics.

**UI patterns:**
- Follow the Monitor module's dashboard pattern for KPI cards
- Use existing `Card` component for metric cards
- Sparklines: simple inline SVG polyline (no external library needed -- the codebase already has inline chart patterns in Monitor)
- Color coding: green for healthy lag (<500ms), yellow for moderate (500-2000ms), red for high (>2000ms)

**Store pattern:**
- Follow `useSyncHistoryStore.ts` / `useSyncScheduleStore.ts` pattern
- Poll metrics via postMessage every 5s while status is 'syncing' or 'paused'
- Keep last 60 metric snapshots for sparkline data (5min of history at 5s intervals)

<action>
1. Create `useCDCMetricsStore.ts` Zustand store with state:
   - `metrics: RealTimeSyncMetrics | null` -- latest snapshot
   - `metricsHistory: RealTimeSyncMetrics[]` -- last 60 snapshots for sparklines
   - `polling: boolean` -- whether metrics polling is active

2. Import `RealTimeSyncMetrics` type from `@sandforge/shared` (it already exists there).

3. Actions:
   - `updateMetrics(m: RealTimeSyncMetrics)` -- set metrics, push to metricsHistory (cap at 60), trim oldest if over.
   - `startPolling()` -- set polling=true, start a 5s interval that posts `realtime:metrics` message via getVscodeApi().postMessage. Store the interval ID.
   - `stopPolling()` -- set polling=false, clear interval.
   - `reset()` -- stop polling, clear metrics and history.

4. Message listener: listen for `realtime:metrics:response` message from extension. On receive, call `updateMetrics(payload.metrics)`.

5. Derived data helpers (as separate exported functions, not in store):
   - `getEventsPerSecondHistory(history: RealTimeSyncMetrics[]): number[]` -- extract eventsPerMinute / 60 from each snapshot
   - `getLagHistory(history: RealTimeSyncMetrics[]): number[]` -- extract currentLagMs from each snapshot
   - `getUptimeSeconds(startedAt: string): number` -- compute seconds since startedAt

6. Tests (useCDCMetricsStore.test.ts):
   - Test updateMetrics stores snapshot and appends to history
   - Test history is capped at 60 entries
   - Test startPolling sets polling=true
   - Test stopPolling clears interval
   - Test reset clears all state
   - Test getEventsPerSecondHistory extracts correct values
   - Test getLagHistory extracts correct values
   - Test getUptimeSeconds computes correct duration
</action>
