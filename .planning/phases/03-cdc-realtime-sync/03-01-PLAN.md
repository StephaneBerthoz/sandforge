# Plan 01: CDC Backend Hardening

## Objective

Fix 4 known bugs in the CDC pipeline (custom object channel naming, swallowed errors, false positive applied status, unbounded timings array), add replay ID persistence to globalState, implement a watchdog timer for stale CometD connections, add handler cleanup on stop to prevent memory leaks, and create an event batcher for efficient WebView delivery. This plan makes the backend solid before any UI work begins.

## Context

The CDC pipeline has three core classes: CDCListener (subscribes to Streaming API), CDCReplicator (applies events to target org), and RealTimeSyncOrchestrator (coordinates both). All three exist and work, but have bugs identified in RESEARCH.md:

1. **CDCListener.buildChannels() line 193**: Custom objects like `MyObj__c` generate wrong channel `/data/MyObj__cChangeEvent` instead of `/data/MyObj__ChangeEvent`. The fix exists in monitor module's `ChangeDataCaptureListener.buildCdcChannel()` -- extract to shared util.
2. **CDCReplicator.applyEvents() line 221**: catch block swallows errors silently. Add error callback.
3. **RealTimeSyncOrchestrator line 97**: Events marked `applied: true` before actual application. Fix: emit with `applied: false`, then emit again after replicator confirms.
4. **CDCReplicator.timings**: Uses slice which creates GC pressure. Replace with ring buffer.

Additional hardening:
- Handler arrays (eventHandlers, connectionHandlers) have no cleanup -- return unsubscribe functions like MessageBroker.on().
- Replay IDs are in-memory only -- persist to globalState via injected persister interface.
- No watchdog for CometD silent disconnects -- add 240s timeout timer.
- Event batching: create CDCEventBatcher class that accumulates events for 150ms then sends a single `realtime:events-batch` message to the WebView.

Patterns to follow:
- `MessageBroker.on()` returns unsubscribe function pattern
- `WebviewStateSync` 16ms debounce pattern (but use 150ms for CDC batching)
- All handler arrays follow push-only pattern currently -- migrate to return-disposable pattern
- Use Zod for the new batch message type in messages.types.ts

1. **Replay ID persistence:**
   - Add a `ReplayIdPersister` interface to CDCListener.ts (or a shared types file): `{ load(orgId: string, objectName: string): Promise<number>; save(orgId: string, objectName: string, replayId: number): Promise<void>; }`.
   - Add optional `replayIdPersister` to CDCListenerConfig.
   - In `handleMessage()`, after updating `this.lastReplayId`, call `this.config.replayIdPersister?.save(this.config.orgId, event.objectApiName, event.replayId)` (fire and forget, catch errors).
   - In `start()`, if persister exists, load the last replay ID for each watched object and use the minimum as the starting replay ID.
   - On 400/403 error during subscription, fall back to -1 (latest) and log warning.

2. **Watchdog timer:**
   - Add `private watchdogTimer: ReturnType<typeof setInterval> | null = null` and `private lastActivityTime = Date.now()`.
   - In `handleMessage()`, update `this.lastActivityTime = Date.now()`.
   - In `connect()`, after successful connection, start a watchdog interval (every 60s). In the callback: if `Date.now() - this.lastActivityTime > 240_000`, force disconnect and reconnect (call `stop()` then `start()` equivalent -- cancel subscriptions, disconnect client, then `connect()` again).
   - In `stop()`, clear the watchdog timer.
   - The watchdog also detects sleep/wake: if `Date.now() - lastActivityTime > 240s`, it means either no events (possible) or a sleep occurred.

3. **CDCEventBatcher:**
   - Create `CDCEventBatcher.ts` class:
     ```
     constructor(postFn: (events: CDCEvent[]) => void, windowMs = 150)
     ```
   - `push(event: CDCEvent)`: add to internal buffer array. If no flush timer running, start one with `setTimeout(flush, windowMs)`.
   - `flush()`: if buffer has events, call `postFn([...buffer])`, clear buffer, clear timer.
   - `dispose()`: flush remaining, clear timer.
   - Ring buffer variant: use a fixed-size array (capacity 10000) with write index for the internal buffer. When capacity is reached, oldest events are dropped.

4. **Batch message type in messages.types.ts:**
   - Add `RealTimeEventsBatchMessage` interface:
     ```typescript
     export interface RealTimeEventsBatchMessage extends BaseMessage {
       type: 'realtime:events-batch';
       payload: {
         events: Array<{
           replayId: number;
           objectApiName: string;
           changeType: string;
           recordIds: string[];
           commitTimestamp: string;
           changedFields: Record<string, unknown>;
           commitUser: string;
           transactionKey: string;
           applied: boolean;
           error?: string;
         }>;
       };
     }
     ```
   - Add to the `ExtensionToWebviewMessage` union type.

5. **Tests:**
   - CDCEventBatcher: test that events are batched within the window, test flush on dispose, test ring buffer overflow drops oldest.
   - CDCListener: test replay ID load/save flow, test watchdog reconnect after 240s silence (use fake timers), test 400 error fallback to -1.
