# Plan 2: Execution + Results UX Enhancements

## Objective

Enhance the Forge execution and results views with five UX improvements: persist execution logs to the store so they survive phase transitions (UX-14), display an ETA during execution (UX-17), add sort/filter to the results table (UX-18), show duration and timestamp in results (UX-19), and make "Forge Again" preserve the config instead of wiping everything (UX-13).

## Context

- **ForgeExecution.tsx** (341 lines) manages logs in local state (`useState<LogEntry[]>`). When the phase changes to `results`, logs are lost.
- **ForgeResults.tsx** (284 lines) shows KPIs, a static table, and action buttons. `handleForgeAgain` calls `reset()` which wipes all state.
- **useForgeStore.ts** (245 lines) has `reset()` that sets `INITIAL_STATE`. No `logs` field, no `forgeAgain()`.
- **LogEntry** type is defined in `LogStream.tsx` — it needs to be importable by the store or re-exported.
- **ForgeExecutionResult** has `duration: number` (ms) and `timestamp: string` (ISO) — neither is displayed.
- The `formatElapsed` utility exists in `packages/webview/src/utils/formatters.ts`.
- **Locked decision**: `setConfig` clears stale plan/complianceReport/metadataDiffs/result but preserves graph/templates/history.
- **Locked decision**: LogStream `hideFilterBar` prop controls internal filter tab visibility.
- **NOTE on store changes**: Plan 01 also adds `setAllNodesIncluded` to useForgeStore. This plan adds `logs`, `addLog`, `clearLogs`, and `forgeAgain`. These are non-overlapping additions to the interface and implementation. To avoid merge conflicts, add your new fields and methods AFTER the existing ones at the END of the interface and the END of the create body (before `reset`).

Add a filter+sort memo:
```typescript
const sortedFilteredNodes = useMemo(() => {
  let filtered = nodes;
  if (statusFilter !== 'all') {
    filtered = filtered.filter((n) => n.status === statusFilter);
  }
  return [...filtered].sort((a, b) => {
    const aVal = a[sortField];
    const bVal = b[sortField];
    if (typeof aVal === 'string' && typeof bVal === 'string') {
      return sortDir === 'asc' ? aVal.localeCompare(bVal) : bVal.localeCompare(aVal);
    }
    if (typeof aVal === 'number' && typeof bVal === 'number') {
      return sortDir === 'asc' ? aVal - bVal : bVal - aVal;
    }
    return 0;
  });
}, [nodes, statusFilter, sortField, sortDir]);
```

Add a `handleSort` callback:
```typescript
const handleSort = useCallback((field: SortField) => {
  setSortField((prev) => {
    if (prev === field) {
      setSortDir((d) => (d === 'asc' ? 'desc' : 'asc'));
      return prev;
    }
    setSortDir('asc');
    return field;
  });
}, []);
```
