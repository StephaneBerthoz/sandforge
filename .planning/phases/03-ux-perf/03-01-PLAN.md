# Plan 1: Discovery UX Enhancements

## Objective

Add four UX enhancements to ForgeDiscovery that improve usability for large orgs: a table/list view alternative to the graph (UX-11), a retry button on discovery errors (UX-20), bulk select/deselect all nodes (UX-21), and a search/filter for nodes by object name (UX-22). These changes make the discovery phase more accessible when dealing with 30+ objects.

## Context

- **ForgeDiscovery.tsx** (228 lines) renders a `SplitView` with `LiveGraph` left and `ForgeNodeDetail` right. It has loading, error, and graph states.
- **useForgeStore** has `toggleNodeIncluded(objectName)` for individual toggles but no bulk action. Need to add `setAllNodesIncluded`.
- The error state (lines 119-131) shows the error message and a Back button — no retry mechanism.
- The discovery request is sent from ForgeInput via `sendMessage(buildMessage('forge:discover', { config }))`. For retry, ForgeDiscovery needs access to `config` from the store and `useSendMessage`/`buildMessage`.
- The `SplitView` component supports `ratio` prop: `50/50`, `60/40`, `70/30`.
- Project conventions: all text via `t('key')`, no `any`, JSDoc on public interfaces, test file in same directory.
- **Locked decision**: `setConfig` clears stale plan/complianceReport/metadataDiffs/result but preserves graph/templates/history.

setAllNodesIncluded(included: boolean): void {
  set((state) => {
    if (!state.graph) return state;
    return {
      graph: {
        ...state.graph,
        nodes: state.graph.nodes.map((n: ForgeGraphNode) => ({ ...n, included })),
      },
    };
  });
},
