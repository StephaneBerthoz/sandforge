# Plan 1: Sync Templates + Step Reduction

## Objective

Add 3 pre-built sync templates (Full Account Hierarchy, Opportunities + Products, Cases + Attachments) and merge the org-selection step (Step 0) with the object-selection step (Step 1) into a single combined step, reducing the wizard from 7 to 6 steps. This delivers SWIZ-03 and SWIZ-04.

## Context

**Existing wizard structure:** SyncPage.tsx defines `SYNC_STEPS` as a 7-element array (select-orgs, configure-objects, field-mapping, transforms, review, execute, results). Step content is rendered conditionally by `currentStep` index. The `useSyncPageData` hook manages all form state including draft auto-save via `useWebviewPersistedState`.

**Seed templates as pattern:** `packages/shared/src/constants/seed-templates.ts` shows the established pattern for pre-built templates -- typed constants with i18n name/description keys, exported as a convenience array. Sync templates follow the same pattern but use partial `SyncConfig` shape (objects + settings, no org IDs).

**Key constraint:** Step index changes ripple through `canGoNext()` switch cases, `useEffect` triggers (field fetch at step 2, PII scan at step 4), and the auto-navigate-to-results effect (currently targets step 6). All must shift down by 1 after the merge.

**SyncConfigStore** (from Phase 01) already handles CRUD for SyncConfig. Templates are read-only constants, not stored in ConfigStore -- they produce a partial config that the user can then save.

**ObjectSetEditor** is a standalone component accepting `entries`, `availableObjects`, `onAdd`, `onRemove`, `onChange` props. It can be embedded directly below the org selectors in the merged step.
