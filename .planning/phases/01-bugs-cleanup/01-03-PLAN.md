# Plan 01-03: Cleanup + BE-08 — Dead Code, Store Hygiene, Filter Dedup, Deprecated File Deletion

## Context

This plan depends on Plans 01-01 and 01-02 completing first (Wave 2). It cleans up dead code, fixes store hygiene, and removes deprecated files. These are all low-risk changes but touch files that Plans 01-01 and 01-02 may have modified (ForgeExecution.tsx, ForgeInput.tsx).

Seven items:
- **CLN-01**: Remove `<MetadataDiffBanner diffs={[]} />` placeholder (always hidden, always empty array)
- **CLN-02**: Wire preview data into estimated graph stats (replace em-dashes with real values when available)
- **CLN-03**: Add `hideFilterBar` prop to LogStream; pass it from ForgeExecution to eliminate duplicate filter tabs
- **CLN-04**: Remove `canPreview` from ForgeInput (it is redundant with auto-preview logic; the button at line 290 needs a different guard or removal)
- **CLN-05**: Convert `logIdCounter` from module-level `let` to `useRef` inside ForgeExecution component
- **CLN-06**: Make `setConfig` in useForgeStore clear stale review-phase artifacts (plan, complianceReport, metadataDiffs, result)
- **BE-08**: Delete the deprecated `ForgeOpsHandler.ts` (already an empty stub, no source imports)

**Key patterns:**
- `INITIAL_STATE` object in useForgeStore.ts (lines 68-79) shows the reset pattern
- LogStream already accepts a `filter` prop from parent; the new `hideFilterBar` prop only controls whether its internal tabs render
- Preview response from `forge:preview:response` returns `{ objectApiName, objectLabel, recordId, fields }` -- for CLN-02 we can show 1 object and the field count from preview

## Must-Haves

- [ ] MH-1: MetadataDiffBanner placeholder call removed from ForgeDiscovery.tsx
- [ ] MH-2: ForgeInput estimated graph stats display preview-derived data (1 object, field count) when preview is loaded

- [ ] MH-4: `canPreview` variable removed from ForgeInput.tsx (button at line 290 uses inline condition or is removed)

- [ ] MH-6: `useForgeStore.setConfig()` resets `plan`, `complianceReport`, `metadataDiffs`, and `result` to their initial values
- [ ] MH-7: `ForgeOpsHandler.ts` is deleted; no source file imports it
- [ ] MH-8: All existing tests pass plus new tests cover each change
- [ ] MH-9: `pnpm typecheck` passes, `pnpm lint:fix` passes

### Task 3: Remove canPreview + store hygiene + delete ForgeOpsHandler (CLN-04, CLN-06, BE-08)

- `packages/webview/src/pages/Forge/ForgeInput.tsx`
- `packages/webview/src/pages/Forge/ForgeInput.test.tsx`
- `packages/webview/src/stores/useForgeStore.ts`
- `packages/webview/src/stores/useForgeStore.test.ts`
- `packages/extension/src/bridge/handlers/ForgeOpsHandler.ts` (DELETE)

**Action:**

1. **CLN-04** -- In `ForgeInput.tsx`:
   - Line 157: `const canPreview = extractRecordId(recordId) !== null && sourceOrgId.length > 0 && !previewLoading;`
   - Line 290: The button uses `disabled={!canPreview}`.
   - Check what this button does. If it is a manual "Preview" or "Refresh" button that calls `handlePreview`, it is now redundant because auto-preview (lines 172-181) already triggers on valid input. Two options:
     a. If the button is a "Refresh preview" action, keep the button but inline the condition: `disabled={!(extractRecordId(recordId) !== null && sourceOrgId.length > 0 && !previewLoading)}`. Then delete the `canPreview` variable.
     b. If the button can be removed entirely (since auto-preview handles it), remove both the button and `canPreview`.
   - The safer option is (a): inline the disabled condition and remove the named variable. This avoids removing UI that users may click manually to refresh.

2. **CLN-06** -- In `useForgeStore.ts`:
   - Update the `setConfig` method (lines 138-140) to also clear stale artifacts:
     ```typescript
     setConfig(config: ForgeConfig): void {
       set({ config, plan: null, complianceReport: null, metadataDiffs: [], result: null });
     },
     ```
   - Do NOT clear `graph` in `setConfig`. The graph is set separately by the discovery flow, and clearing it here would cause a flash of empty state if `setConfig` is called before discovery completes. The graph is correctly reset by `setGraph` when new discovery results arrive.
   - Do NOT clear `templates` or `history` -- those are user data that persists across forge runs.

3. **BE-08** -- Delete `packages/extension/src/bridge/handlers/ForgeOpsHandler.ts`:
   - Delete the file entirely.
   - Check for a corresponding test file `ForgeOpsHandler.test.ts` -- if it exists, delete it too.
   - Verify no source file imports `ForgeOpsHandler` (research confirms no source-level imports remain).

4. Update tests:
   - In `ForgeInput.test.tsx`: Remove any test that references `canPreview` by name. Verify that the preview button (if kept) is disabled/enabled based on the inlined condition.
   - In `useForgeStore.test.ts`: Add a test that calling `setConfig(newConfig)` resets `plan` to null, `complianceReport` to null, `metadataDiffs` to `[]`, and `result` to null, while preserving `graph`, `templates`, and `history`.
