# Plan 02-01: Backend Wiring (WIRE-01..05 handler side)

## Objective

Wire 5 existing monitor services (ErrorLogMonitor, UserSessionMonitor, ApexLogAnalyzer, SandboxRefreshTracker, HealthCheck) to MonitorOpsHandler bridge handlers, define the message type contracts in shared, add i18n keys for all new panels, and register the new routes. This is the backend half of the WIRE requirements; it establishes the message protocol that the UI panels (Plan 02-02) will consume.

## Context

**Existing services:** All 5 services are fully implemented in `packages/extension/src/modules/monitor/` with unit tests. They use dependency-injected query functions, not raw connections. They must be instantiated as class-level fields on MonitorOpsHandler (like `healthCalculator` and `trendStorage`), not re-created per request (their caches are stateful).

**Service instantiation pattern (critical):**
- `ErrorLogMonitor`, `UserSessionMonitor`, `ApexLogAnalyzer`, `SandboxRefreshTracker` all require a query function in their constructor. Since the actual jsforce connection is only available at call-time (after `getJsforceConnection`), these services need a "permanent" query function that will be called with different closures per request. The recommended approach: create each service with a query function that stores a mutable connection reference, then update that reference inside each handler method before calling `fetch()`. However, looking at the actual service APIs more carefully:
  - `ErrorLogMonitor(queryFn)` -- queryFn is `(orgId, since) => Promise<ErrorLogEntry[]>`. The queryFn is called inside `fetch()`.
  - The simplest correct pattern: instantiate each service once with a query function that captures `this` (the handler) and calls `getJsforceConnection` + `queryAll` internally. This way the service is long-lived but gets a fresh connection on each call.

**HealthCheck (WIRE-05):** Does NOT get its own message type. Instead, it is called inside the existing `handleRefresh` method after the other data is fetched, and its `OrgHealthStatus` result is added to the `monitor:data` response payload as `orgHealthStatus`. The `HealthSignalProvider` functions should be built from data already available in handleRefresh (limits, jobs, error count) to avoid extra SOQL calls.

**SandboxRefreshTracker:** Per Pitfall 9 in research, do NOT pass an `onRefreshDetected` callback -- omit it to avoid flooding notifications on first fetch.

**Dual registration:** Each new message type must be added to both:
1. The `MONITOR_TYPES` Set in MonitorOpsHandler
2. The `route([...], this.monitorHandler)` array in ExtensionHandlers.registerAll()

**Response naming convention:** Request `monitor:X` -> response `monitor:X:response`.

**Handler pattern:** Follow `handleStorage`/`handleDeployments` exactly -- log `[RX]`, extract `payload.orgId`, `getJsforceConnection`, `queryAll` with typed record shape, `checkApiLimits`, map to response shape, `buildResponse`, `broker.postToWebview`, log `[TX]`, catch with `sendHandlerError`.

**SOQL objects:**
- ErrorLogMonitor: `ApexLog` (NOT `ApexDebugLog`) -- `SELECT Id, Operation, Status, DurationMilliseconds, LogLength, StartTime, LogUser.Username FROM ApexLog WHERE Status != 'Success' ORDER BY StartTime DESC LIMIT 50`
- UserSessionMonitor: `AuthSession` -- `SELECT Id, UsersId, LoginType, SessionType, CreatedDate, SourceIp FROM AuthSession ORDER BY CreatedDate DESC LIMIT 100`
- ApexLogAnalyzer: `ApexLog` -- `SELECT Id, Operation, Status, DurationMilliseconds, LogLength, StartTime, LogUser.Username FROM ApexLog ORDER BY StartTime DESC LIMIT 20`
- SandboxRefreshTracker: `SandboxProcess` -- `SELECT Id, SandboxName, Status, CreatedDate, Description FROM SandboxProcess ORDER BY CreatedDate DESC LIMIT 20`

   const apiLimitsProvider: HealthSignalProvider = async (orgId: string) => {
     try {
       const conn = await getJsforceConnection(orgId, this.deps.orgRegistry, this.deps.orgManager);
       const limitsRaw = await this.getOrFetchLimits(orgId, conn);
       const apiEntry = limitsRaw['DailyApiRequests'] as { Max: number; Remaining: number } | undefined;
       const pct = apiEntry ? Math.round(((apiEntry.Max - apiEntry.Remaining) / apiEntry.Max) * 100) : 0;
       const status = pct > 80 ? 'critical' as const : pct > 60 ? 'warning' as const : 'ok' as const;
       return { name: 'apiLimits', status, score: 100 - pct, message: `API usage at ${pct}%` };
     } catch { return { name: 'apiLimits', status: 'ok' as const, score: 100, message: 'Unable to fetch limits' }; }
   };

   const storageProvider: HealthSignalProvider = async (orgId: string) => {

       const storageEntry = limitsRaw['DataStorageMB'] as { Max: number; Remaining: number } | undefined;
