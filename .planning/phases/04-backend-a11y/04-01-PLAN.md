# Plan 01: Backend Error Handling + Timeouts

## Objective

Harden the forge backend handlers with structured error payloads (code + retryable flag), configurable timeouts on plan/compliance/metadata-diff operations, operation lifecycle events for all three, and include operationId in forge:execute:response. This makes the backend production-grade with actionable error information for the frontend.

## Context

- `sendHandlerError` in HandlerTypes.ts currently sends `{ message: string }` only. It must support `{ message, code, retryable }` without breaking existing callers (SeedOpsHandler, MonitorHandler, etc. all use it with just 4 args).
- `TimeoutManager` already exists at `packages/extension/src/core/engine/TimeoutManager.ts` and is used by SeedOpsHandler as a reference pattern. Import and use the same class.
- `sendOperationStarted`/`sendOperationCompleted`/`sendOperationFailed` already exist in HandlerTypes.ts and are used by handleDiscover and handleExecute. The pattern is established.
- ForgeHandler.ts line 358: `buildResponse(this.deps, msg, 'forge:execute:response', { result })` must become `{ result, operationId }`.
- Existing test files exist for both HandlerTypes.ts and ForgeHandler.ts. Extend them, do not replace.

The new signature:
```typescript
export function sendHandlerError(
  deps: Pick<HandlerDeps, 'log' | 'broker' | 'nextId'>,
  context: string,
  messageType: string,
  err: unknown,
  code?: string,
  retryable?: boolean,
): void
```

The payload becomes:
```typescript
payload: { message, code: code ?? 'UNKNOWN', retryable: retryable ?? false }
```

This is backward-compatible -- all existing callers omit code/retryable and get defaults.

3. Test that sendHandlerError with only code sends retryable=false default

3. **handlePlanRequest** -- wrap with timeout and lifecycle:
   - Generate `operationId = 'forge-plan-${this.deps.nextId()}'`
   - Call `sendOperationStarted(this.deps, operationId, 'forge', 'Generating execution plan')`
   - Wrap `this.planGenerator.generate(graph)` in `new TimeoutManager(PLAN_TIMEOUT_MS).withTimeout('forge:plan', () => ...)`
   - On success: `sendOperationCompleted(this.deps, operationId, { waveCount: plan.waves?.length ?? 0 })`
   - On catch: call `sendHandlerError` with `code='TIMEOUT'` and `retryable=true` if error is TimeoutError, else `code='PLAN_ERROR'` and `retryable=false`. Also call `sendOperationFailed`.

4. **handleComplianceRequest** -- same pattern:
   - `operationId = 'forge-compliance-${this.deps.nextId()}'`
   - `sendOperationStarted(this.deps, operationId, 'forge', 'Generating compliance report')`
   - Wrap `this.complianceService.generate(...)` in `new TimeoutManager(COMPLIANCE_TIMEOUT_MS).withTimeout(...)`
   - On success: `sendOperationCompleted`
   - On catch: structured error with appropriate code. `sendOperationFailed`.

5. **handleMetadataDiffRequest** -- same pattern:
   - `operationId = 'forge-metadata-diff-${this.deps.nextId()}'`
   - `sendOperationStarted(this.deps, operationId, 'forge', 'Comparing metadata schemas')`
   - Wrap `this.metadataDiff.compare(...)` in `new TimeoutManager(METADATA_DIFF_TIMEOUT_MS).withTimeout(...)`
   - On success: `sendOperationCompleted`
   - On catch: structured error with appropriate code. `sendOperationFailed`.

6. **operationId in execute response** -- In `handleExecute`, change line ~358:
   From: `buildResponse(this.deps, msg, 'forge:execute:response', { result })`
   To: `buildResponse(this.deps, msg, 'forge:execute:response', { result, operationId })`
