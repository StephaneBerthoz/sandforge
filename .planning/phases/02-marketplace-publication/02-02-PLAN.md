# Plan 02: User Documentation

## Objective

Create practical user documentation for SandForge's first Marketplace release. Getting-started guide, one page per core module, FAQ with troubleshooting. Update both READMEs (root and extension) with doc links. All docs are English-only, practical how-to style.

## Context

- Root `README.md` has comprehensive feature list but "Screenshots coming soon" placeholder
- `packages/extension/README.md` is the Marketplace listing page — must be compelling
- No user docs exist yet (only `docs/FULL-PROMPT.md` and `docs/USAGE-STRATEGY.md` which are dev docs)
- 6 core modules: Seed, Sync, Monitor, Compare, DataOps, Automation
- Plus secondary features: AI assistant, Autopilot, Organizations, Reports
- App is 100% WebView UI — docs should reference UI elements, not CLI commands
- i18n: docs in English only (other languages deferred)

<action>
Create `docs/faq.md` combining FAQ and troubleshooting:

**FAQ section** (~10 questions):
- What Salesforce editions are supported?
- Do I need a paid Salesforce org?
- Does SandForge modify production data? (answer: NO — production guard)
- How does AI data generation work? Which LLMs?
- Can I use SandForge without AI features?
- Is my data sent to external services?
- How do I update SandForge?
- What's the difference between Seed and Sync?
- Can I automate recurring operations?
- Does SandForge support Salesforce DX / scratch orgs?

**Troubleshooting section** (~8 items):
- Extension not activating → check VSCode version, reload window
- Can't connect to org → verify `sf org list`, re-authenticate
- Bulk operations failing → check API limits via Monitor, reduce batch size
- Slow performance → check concurrent operations setting, check org tier limits
- SOQL query errors → check field-level security, use NL2SOQL for assistance
- WebView blank/white → clear webview cache, reload window
- Import/export issues → check file format (CSV/JSON), encoding (UTF-8)
- Governor limit warnings → use Monitor to track, reduce batch size

Read actual error handling patterns in the codebase to ensure troubleshooting steps are accurate.
</action>
