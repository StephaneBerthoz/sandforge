# Plan 03: Sync History & Schedule UI

## Objective

Build the webview UI for sync history browsing (HIST-02 through HIST-05) and schedule management (SCHED-01, SCHED-02). This includes Zustand stores for state management, a paginated history table with detail view and re-run capability, CSV/JSON export, a visual cron schedule builder, and a schedule management panel. All components integrate into the existing SyncPage as new tabs or sections.

## Context

**Phase 01 deliverables to use:**
- `DataTable` (packages/webview/src/components/ui/DataTable.tsx) -- has virtual scrolling via `enableVirtualization` prop and `@tanstack/react-virtual`. Use for history list.
- `Pagination` (packages/webview/src/components/ui/Pagination.tsx) -- page size selector + navigation. Wire to history list.
- `SkeletonTable` -- use as loading state for history and schedule panels.

**Existing UI patterns:**
- Zustand stores in `packages/webview/src/stores/` -- follow `useNotificationStore` or `useRecentOpsStore` pattern. Each store sends messages via `vscode.postMessage` and receives responses.
- `SyncPage` (packages/webview/src/pages/Sync/SyncPage.tsx) -- currently wizard-based. Add History and Schedules as tabs alongside the existing sync flow.
- `date-fns` is installed in webview for date formatting. Use `format`, `formatDistanceToNow`, `formatDuration`.
- `useTranslation` (react-i18next) for all visible text -- never hardcode strings.
- All components are functional React with hooks. No class components.

**Message protocol (defined in Plan 01):**
- `sync:history:list` / `sync:history:list:response` -- fetch all history entries
- `sync:history:detail` / `sync:history:detail:response` -- fetch single entry
- `sync:history:rerun` -- trigger re-execution with snapshot config
- `sync:history:export` / `sync:history:export:response` -- export data
- `sync:schedule:list` / `sync:schedule:list:response` -- fetch schedules
- `sync:schedule:upsert` / `sync:schedule:upsert:response` -- create/update
- `sync:schedule:toggle` / `sync:schedule:toggle:response` -- pause/resume
- `sync:schedule:delete` / `sync:schedule:delete:response` -- remove

**Types from Plan 01:**
- `SyncHistoryEntry` -- id, configSnapshot, result, startTime, endTime, triggeredBy, scheduleId
- `SyncScheduleEntry` -- id, name, configId, cron, timezone, enabled, maxRetries, notifyOnComplete, notifyOnFailure, nextRunAt, lastRunAt, lastResult, createdAt, updatedAt, version
- `ExportFormat` -- 'csv' | 'json'

**Cron builder design (from research):**
- No existing React cron builder fits VSCode aesthetic. Build a simple visual picker.
- Visual mode: dropdowns for frequency preset (Every hour, Every day, Every week, Every month, Custom), then contextual pickers (hour/minute for daily, day-of-week for weekly, day-of-month for monthly).
- Advanced mode: raw text input for 5-field cron string.
- Always validate via displaying the "Next 3 runs" computed client-side (can use a simple preview, actual validation happens server-side with cron-parser).
- Timezone selector: use `Intl.supportedValuesOf('timeZone')` to populate a searchable dropdown. Default to `Intl.DateTimeFormat().resolvedOptions().timeZone`.

Create `useSyncHistoryStore` as a Zustand store following existing store patterns in the codebase.

State:
```typescript
interface SyncHistoryState {
  entries: SyncHistoryEntry[];
  selectedEntry: SyncHistoryEntry | null;
  loading: boolean;
  error: string | null;
  // Actions
  fetchHistory: () => void;
  fetchDetail: (entryId: string) => void;
  clearSelection: () => void;
  rerun: (entryId: string) => void;
  exportHistory: (format: ExportFormat, entryIds?: string[]) => void;
  handleMessage: (message: unknown) => void;
}
```

`fetchHistory` sends `{ type: 'sync:history:list' }` via `vscode.postMessage`.
`fetchDetail` sends `{ type: 'sync:history:detail', payload: { entryId } }`.
`rerun` sends `{ type: 'sync:history:rerun', payload: { entryId } }`.
`exportHistory` sends `{ type: 'sync:history:export', payload: { format, entryIds } }`.
`handleMessage` processes incoming responses and updates state (entries, selectedEntry, loading, error).

For export response handling: when `sync:history:export:response` arrives with data, trigger a download by creating a Blob and using a hidden anchor element (standard webview download pattern), or send the data back as a file-save request.

Create `useSyncScheduleStore` similarly:

State:
```typescript
interface SyncScheduleState {
  schedules: SyncScheduleEntry[];
  loading: boolean;
  error: string | null;
  // Actions
  fetchSchedules: () => void;
  upsertSchedule: (schedule: Omit<SyncScheduleEntry, 'nextRunAt' | 'lastRunAt' | 'lastResult'>) => void;
  toggleSchedule: (scheduleId: string, enabled: boolean) => void;
  deleteSchedule: (scheduleId: string) => void;
  handleMessage: (message: unknown) => void;
}
```

Same postMessage/handleMessage pattern.

Tests for each store (mock `vscode.postMessage`):
1. `fetchHistory` sends correct message type
2. `handleMessage` with list response updates entries and sets loading=false
3. `handleMessage` with detail response updates selectedEntry
4. `fetchSchedules` sends correct message type
5. `handleMessage` with schedule list response updates schedules
6. `toggleSchedule` sends correct message with scheduleId and enabled flag
</action>

**CronScheduleBuilder.tsx:**

A form component for creating/editing cron schedules. Props:
```typescript
interface CronScheduleBuilderProps {
  initialCron?: string;
  initialTimezone?: string;
  onSubmit: (data: { name: string; cron: string; timezone: string; configId: string; maxRetries: number; notifyOnComplete: boolean; notifyOnFailure: boolean }) => void;
  onCancel: () => void;
  configs: Array<{ id: string; name: string }>; // available sync configs to schedule
}
```

Layout:
1. **Name** text input for the schedule name.
2. **Sync Config** selector dropdown -- pick which saved sync config to schedule.
3. **Frequency mode** toggle: "Simple" / "Advanced"
   - Simple mode: preset dropdown (Every hour, Every day at [time], Every week on [day] at [time], Every month on [date] at [time]). Each preset reveals relevant pickers (hour:minute selector, day-of-week buttons, day-of-month dropdown). Generates the 5-field cron string from selections.
   - Advanced mode: raw text input for 5-field cron string with placeholder `'* * * * *'` and help text explaining fields (minute hour day-of-month month day-of-week).
4. **Timezone** searchable Select populated with `Intl.supportedValuesOf('timeZone')`. Default to user's local timezone via `Intl.DateTimeFormat().resolvedOptions().timeZone`.
5. **Options:** max retries (number input, default 3), notify on complete (checkbox), notify on failure (checkbox, default true).
6. **Preview:** display "Next 3 scheduled runs" computed client-side. Since `cron-parser` is only in the extension package, compute a simple preview: for Simple mode, calculate the next 3 dates from the selections. For Advanced mode, show the raw cron and note "Validated on save". Alternatively, if the cron preview is complex, just show the human-readable description of the cron (e.g., "Every Monday at 9:00 AM UTC").
7. **Submit** and **Cancel** buttons.

State management: use React `useState` for form fields. On submit, call `onSubmit` with the assembled data.
