# Plan 01-01: Infrastructure -- Pagination, Cache Management, Virtual Scrolling Install

## Objective

Build the foundational infrastructure that all subsequent Phase 01 plans and later phases depend on: a reusable Pagination component, the @tanstack/react-virtual package installation, centralized cache management with org-switch invalidation, and the cache:invalidate-all message handler. This enables SCALE-01 (pagination), SCALE-02 (virtual scrolling install), SCALE-05 (cache audit), and POLISH-06 (org-switch cache invalidation).

## Context

**Existing patterns:**
- `SchemaCache` (packages/extension/src/core/metadata/SchemaCache.ts) is the primary cache -- it has TTL, LRU eviction, `clear()`, `invalidateByPrefix()`, and `purgeExpired()` methods but no max memory limit or centralized registry.
- `MetadataReader` uses `SchemaCache` internally. The `/limits` and `/orgInfo` caches are in-memory Maps in various handlers.
- The `OrgSwitcher` component (packages/webview/src/components/OrgSwitcher/OrgSwitcher.tsx) uses `useOrgStore` -- when org changes, caches must be invalidated.
- Messages between extension and webview are typed in `packages/shared/src/types/messages.types.ts` and routed through `MessageBroker`.
- All text uses `t('key')` i18n. All 6 locale files must be updated.
- @tanstack/react-table and @tanstack/react-query are already installed in webview.

**Cache audit scope (SCALE-05):** Review all TTLs across SchemaCache (5min default), limits cache (30s), OrgInfo cache (5min). Add `maxSizeBytes` configuration. Ensure `purgeExpired()` runs on a timer. Create a `CacheManager` singleton that tracks all cache instances and provides `invalidateAll()`.

<action>
**CacheManager** (packages/extension/src/core/cache/CacheManager.ts):
- Singleton class with `register(name: string, cache: { clear(): void; purgeExpired?(): number; size: number })` method
- `invalidateAll(): void` -- calls `clear()` on every registered cache
- `purgeAllExpired(): number` -- calls `purgeExpired()` on caches that support it, returns total purged
- `getStats(): Array<{ name: string; size: number }>` -- returns cache sizes for diagnostics
- `dispose(): void` -- clears the purge interval and all caches
- Constructor starts a `setInterval` that calls `purgeAllExpired()` every 60 seconds
- JSDoc on all public methods

**SchemaCache updates:**
- Add `maxSizeBytes?: number` to constructor options (default: 5MB)
- Add rough size estimation: track `JSON.stringify(data).length` per entry in a `sizeMap`
- When `set()` would exceed `maxSizeBytes`, evict LRU entries until under limit
- Add `estimatedBytes` readonly getter
- Existing tests must still pass; add tests for maxSizeBytes eviction

**CacheHandler** (packages/extension/src/bridge/handlers/CacheHandler.ts):
- Handles `cache:invalidate-all` message: calls `CacheManager.getInstance().invalidateAll()`
- Handles `cache:get-stats` message: returns stats from `CacheManager.getInstance().getStats()`
- Register in the handler registry pattern used by other handlers

**Message types** (packages/shared/src/types/messages.types.ts):
- Add `cache:invalidate-all` (no payload) and `cache:get-stats` / `cache:stats-response` message types

**useOrgSwitchInvalidation** (webview hook):
- Subscribes to `useOrgStore` changes on `selectedOrgId`
- When selectedOrgId changes (and previous was not null/undefined), sends `cache:invalidate-all` message via `postMessage`
- Shows a brief "Refreshing..." notification via `useNotificationStore.addNotification()` with autoDismissMs: 2000
- Tests: mock store changes, verify postMessage called, verify notification added
