# Plan 01-04: Virtual Scrolling Integration -- DataTable, VirtualList, VirtualCombobox

## Objective

Apply the @tanstack/react-virtual library (installed in Plan 01-01) to create virtualized variants of the core list components (SCALE-02). This enables smooth rendering of 1000+ items in DataTable, object selectors, sync history, and CDC event feeds. The virtual scrolling components are reusable building blocks consumed by Phase 02 (sync history), Phase 03 (CDC event feed), and Phase 05 (CSV preview).

## Context

**Existing DataTable:**
- `DataTable` (packages/webview/src/components/ui/DataTable.tsx) renders all rows via `.map()` -- works fine for <100 rows but will choke on 1000+ records.
- Has sortable columns, sticky header, striped rows, empty state, onRowClick, motion animations.
- Props: `columns`, `data`, `keyExtractor`, `onRowClick`, `emptyMessage`, `className`, `stickyHeader`, `striped`.
- Adding virtualization must be backward compatible -- existing callers must not break.

**@tanstack/react-virtual v3 API:**
- `useVirtualizer({ count, getScrollElement, estimateSize })` returns `virtualizer` with `getVirtualItems()`, `getTotalSize()`.
- Virtual items have `index`, `start`, `size` properties.
- Requires a scroll container ref and absolute positioning of virtual items.

**Object selectors in the codebase:**
- Multiple pages have object picker dropdowns (Seed wizard, Sync wizard, Compare page). These currently render all 200-2000 Salesforce objects in a dropdown.
- A `VirtualCombobox` component will replace these with a searchable, virtualized dropdown.

**Pagination integration:**
- DataTable with virtualization does NOT need pagination (virtual scrolling IS the solution for large lists).
- DataTable WITHOUT virtualization should use the Pagination component from Plan 01-01.
- The `enableVirtualization` prop determines which mode is used.

<action>
**Extend DataTable with virtualization:**

Add new optional props to `DataTableProps`:
- `enableVirtualization?: boolean` (default false -- backward compatible)
- `estimatedRowHeight?: number` (default 40)
- `maxHeight?: string` (default '400px' -- scroll container height when virtualized)

When `enableVirtualization` is true:
- Wrap the table body in a scroll container div with `ref={scrollContainerRef}` and `overflow-y: auto` and `maxHeight`
- Use `useVirtualizer` from @tanstack/react-virtual:
  ```
  const virtualizer = useVirtualizer({
    count: sortedData.length,
    getScrollElement: () => scrollContainerRef.current,
    estimateSize: () => estimatedRowHeight,
    overscan: 5,
  });
  ```
- Render only `virtualizer.getVirtualItems()` rows, positioned absolutely within a container of `virtualizer.getTotalSize()` height
- Each virtual row uses `transform: translateY(${item.start}px)` for positioning
- Sticky header remains outside the virtual scroll container
- Disable framer-motion stagger animations when virtualized (they conflict with absolute positioning)
- Sorting still works: sort the full dataset, virtualizer renders the sorted view

When `enableVirtualization` is false:
- Behavior is identical to current implementation (no changes)

**Update existing tests:**
- All existing DataTable tests must still pass (they don't set enableVirtualization so they use the non-virtual path)
- Add new tests:
  - Virtual mode renders only visible rows (create 500 items, verify DOM has ~overscan+visible count, not 500)
  - Virtual mode with sorting: sort, verify visible items are sorted
  - Sticky header works in virtual mode
  - onRowClick works in virtual mode
  - Empty state still renders correctly in virtual mode
</action>
