# Plan 03-07: Multi-org overview + visibility-gated polling

**Requirements covered:** MON-07 (multi-org overview lists N orgs with health status + drill-down).

## Goal

Ship multi-org overview as the new default Monitor landing — backend `FleetSummaryService` polls connected orgs through ConnectionPool + p-limit(3) with cache + backoff; webview `MonitorOverviewPage` subscribes via Zustand `useFleetStore` (Record-based, not Map); `useVisibilityGate` posts `monitor:visibility` on `document.visibilitychange` to pause polling when the panel isn't visible. Demoable via Playwright spec with 3 mock orgs + drill-down + visibility-hidden suspends polling.

- **03-01** ships the `monitor:fleet:summary` envelope shape in `MetricEvent.ts`. This plan extends with request/response/visibility envelope types.
- **03-03** ships `MonitorRegistry.setVisibility(hidden)` — this plan posts `monitor:visibility` from webview, extension routes it to `monitorOrchestrator.registry.setVisibility()`. Plan 03-03 and 03-07 both touch the visibility gate but on opposite sides (extension-side gate vs webview-side trigger), no file overlap.

No file overlap with sibling Wave 2 plans:
- **03-04** writes `DriftDetector` + `DriftFeed.tsx` — disjoint UI page, disjoint backend.
- **03-05** writes `AnomalyEngine.ts` — disjoint.
- **03-06** writes `ReportExporter.ts` + adds `monitor:export:*` to `messages.types.ts`. This plan adds `monitor:fleet:*` and `monitor:visibility` — append-only different message types. Both touch `extension.ts` for handler registration — append-only different handlers. NO conflict.
- 03-04 and 03-07 both append to `mock-responses.ts` — different factory exports, append-only.

## Non-goals

- **Server-side push for fleet overview** — CONTEXT non-goal #4 explicitly forbids; pure 60s poll. CDC + Pub/Sub stay in Phase 05.
- **Adding a new charting library** — RESEARCH §1 + CONTEXT non-goal #2; gauges use Recharts (already in webview deps) or plain SVG.
- **Adding `useFleetStore` to global Zustand state.** RESEARCH §3 P-03.7 M5 + Phase 02 store-slice strategy: each store slice is its own hook. New file, isolated.
- **Replacing existing single-org Monitor page.** Drill-down navigates TO it; the existing page is preserved.
- **Detecting "stale" beyond a 5-min red badge.** Per-org backoff doubles intervals; UI shows a single "stale" pill — no fancy categorization.
- **Per-user fleet preferences (favorites, ordering).** Out of scope for v1.3.0 — alphabetical sort.
- **Migrating audit M5 fix to existing Zustand stores.** Per RESEARCH §3 P-03.7: "Apply to NEW monitor stores" — only the new `useFleetStore` (and any `useMonitorMetricsStore` introduced) MUST use Record. Existing stores left as-is for Phase 06.

## Pitfalls mitigated (RESEARCH §3)

- **P-03.5 (Multi-org spawns N parallel jsforce connections)** — reuse ConnectionPool, wrap in `pLimit(3)`, 60s cache, per-org backoff doubling.
- **P-03.7 audit M1 (visibility-gated polling)** — `document.visibilitychange` listener in `useVisibilityGate` posts `monitor:visibility` envelope; extension calls `registry.setVisibility(hidden)` AND `FleetSummaryService.setVisibility(hidden)`.
- **P-03.7 audit M5 (Map → Record)** — `useFleetStore` uses `Record<string, OrgFleetSummary>` to avoid Zustand referential-equality issues with Map values.
- **P-03.7 audit H7 (BridgeProvider mount-only useEffect)** — boot sequencing: `monitor:fleet:summary:request` fires AFTER `bridge:hello` round-trip, NOT in `useEffect(() => …, [])` directly.

```typescript
import pLimit from 'p-limit';
import type { ConnectionPool } from '../../core/connection/ConnectionPool';
import type { HealthCheck } from './HealthCheck';
import type { AlertEngine } from './AlertEngine';
import type { Logger, TelemetryService } from '../../core/types';
import type { OrgFleetSummary } from '@sandforge/shared';

export interface FleetSummaryDeps {
  pool: ConnectionPool;
  healthCheck: HealthCheck;
  alertEngine: AlertEngine;
  logger?: Logger;
  telemetry?: TelemetryService;
  pollIntervalMs?: number;       // default 60_000
  cacheTtlMs?: number;           // default 60_000
  maxConcurrent?: number;        // default 3 — P-03.5 p-limit
  now?: () => number;
}

export class FleetSummaryService {
  private cache = new Map<string, { summary: OrgFleetSummary; cachedAt: number }>();
  private failureStreaks = new Map<string, number>();   // orgId -> consecutive-fail count
  private nextPollAt = new Map<string, number>();       // orgId -> when to poll again (backoff)
  private hidden = false;
  private timer?: ReturnType<typeof setInterval>;
  private limit: ReturnType<typeof pLimit>;

  constructor(private deps: FleetSummaryDeps) {
    this.limit = pLimit(deps.maxConcurrent ?? 3);
  }

  setVisibility(hidden: boolean): void { this.hidden = hidden; }      // audit M1

  start(): void {
    if (this.timer) return;
    this.timer = setInterval(() => this.tickIfVisible(), this.deps.pollIntervalMs ?? 60_000);
  }

  dispose(): void {
    if (this.timer) { clearInterval(this.timer); this.timer = undefined; }
    this.cache.clear();
    this.failureStreaks.clear();
    this.nextPollAt.clear();
  }

  private async tickIfVisible(): Promise<void> {
    if (this.hidden) return;     // audit M1 — pause when document.hidden
    // Eagerly refresh stale orgs; lazy ones served from cache
  }

  /** Public for the bridge handler: returns summaries for orgIds (default: all connected). */
  async getSummary(orgIds: string[]): Promise<OrgFleetSummary[]> {
    const now = this.deps.now?.() ?? Date.now();
    const cacheTtl = this.deps.cacheTtlMs ?? 60_000;
    const tasks = orgIds.map((orgId) => this.limit(async () => {
      // Cache hit
      const cached = this.cache.get(orgId);
      if (cached && now - cached.cachedAt < cacheTtl) return cached.summary;
      // Backoff respected
      const nextAt = this.nextPollAt.get(orgId) ?? 0;
      if (now < nextAt && cached) return { ...cached.summary, stale: true };
      try {
        const summary = await this.fetchOne(orgId);
        this.cache.set(orgId, { summary, cachedAt: now });
        this.failureStreaks.set(orgId, 0);
        this.nextPollAt.set(orgId, now + (this.deps.pollIntervalMs ?? 60_000));
        return summary;
      } catch (err) {
        const fails = (this.failureStreaks.get(orgId) ?? 0) + 1;
        this.failureStreaks.set(orgId, fails);
        // P-03.5 backoff: 60 → 120 → 240 capped at 600
        const backoffMs = Math.min(60_000 * Math.pow(2, Math.min(fails - 1, 4)), 600_000);
        this.nextPollAt.set(orgId, now + backoffMs);
        this.deps.logger?.warn(`[FleetSummary] ${orgId} failed (${fails} consecutive). Backing off ${backoffMs}ms.`);
        // Return last-known cached summary marked stale (or a degraded synthesis)
        if (cached) return { ...cached.summary, stale: true };
        return { orgId, name: orgId, healthScore: 0, lastUpdated: new Date(now).toISOString(), alertCount: 0, recentAlerts: [], stale: true };
      }
    }));
    return Promise.all(tasks);
  }

  /** Private: fetch one org's summary using ConnectionPool (P-03.5). */
  private async fetchOne(orgId: string): Promise<OrgFleetSummary> {
    // Acquire from pool — does NOT create a new jsforce connection
    const conn = await this.deps.pool.acquire(orgId);
    try {
      const health = await this.deps.healthCheck.computeHealth(orgId);
      const alerts = this.deps.alertEngine.getRecentAlerts(orgId, 3);
      return {
        orgId,
        name: conn.userInfo?.organizationName ?? orgId,
        healthScore: health.score ?? 0,
        lastUpdated: new Date().toISOString(),
        alertCount: alerts.length,
        recentAlerts: alerts.map((a) => ({ id: a.id, severity: a.severity, metric: a.metric, triggeredAt: a.triggeredAt })),
        stale: false,
      };
    } finally {
      await this.deps.pool.release(orgId, conn);
    }
  }
}
```

Note: the exact public signatures of `ConnectionPool.acquire/release` and `HealthCheck.computeHealth` may differ — match the existing API. The pattern (acquire from pool, never `new Connection()`) is the invariant.
