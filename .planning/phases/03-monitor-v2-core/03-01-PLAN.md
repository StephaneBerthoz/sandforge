# Plan 03-01: MetricBus + Zod Event Schemas

**Requirements covered:** MON-01 (MetricBus single source of metric events; trackers publish, panels subscribe).

## Goal

Ship the substrate event bus + the Zod-validated `MetricEvent` discriminated union so a probe can emit a typed sample and a subscriber (test or webview) receives it through the bus — closing the v1.2.1 anti-pattern where adding a 6th metric required updating N point-to-point handlers.

## Depends on

Nothing else in Phase 03. This is the very first substrate plan and Wave 2 features (Drift v2, Anomaly, Overview) all depend on the contract this plan ships. No file overlap with sibling plans:
- **03-02** writes `TimeSeriesStore.ts` only — does not touch `MetricBus.ts` / `MetricEvent.ts` / `messageSchemas.ts`.
- **03-03** writes `MonitorRegistry.ts` + adapters in each existing tracker file — consumes `MetricBus` but does not modify it.
- **03-04 / 03-05 / 03-07** add new event subtypes to `MetricEvent.ts` BUT each plan owns its own discriminant string (`drift:detected`, `anomaly:detected`, `fleet:summary`) so merges are append-only and conflict-free per discriminant.

## Non-goals

- **Replacing `AlertEngine`.** AlertsPanel keeps its existing pipeline (CONTEXT non-goal #1). Anomaly/drift events plug INTO it via Plan 03-05 / 03-04 bridging, not via MetricBus directly.
- **Adding a new event-bus library** (`mitt`, `nanoevents`, `eventemitter3`). Reuse the existing `TypedEventEmitter` per RESEARCH §1.
- **Adding `MetricBus` to the global `CoreServices` object.** Per RESEARCH §2 ("CoreServices DI contract"), `metricBus` is a singleton field on `MonitorOrchestrator`, not in `Services`. Phase 03 must not balloon the DI surface.
- **Folding Phase 05 CDC events into the discriminated union right now** — keep the union extensible (open) but do NOT add `cdc:event` variants in this plan (CONTEXT open question Q4, deferred to v1.4).
- **Closing the union with a giant `enum`** — leave it as `discriminatedUnion('type', [...])` so Phase 04 / 05 can append cleanly (P-03.8).

## Pitfalls mitigated (RESEARCH §3)

- **P-03.8 (Discriminated-union exhaustiveness)** — addressed via `assertNever()` helper + Zod `discriminatedUnion`.
- **P-03.9 (Bridge event flood)** — addressed via 250 ms coalescing window into `monitor:metrics:batch`.

<action>
Create `packages/extension/src/modules/monitor/MetricBus.ts`. Class `MetricBus extends TypedEventEmitter<MetricEventTypeMap>`.

Constructor takes `{ bridge?: BridgeProvider, logger?: Logger, coalesceWindowMs?: number }` (default `coalesceWindowMs = 250`).

Public API:
- `emit<T extends keyof MetricEventTypeMap>(type: T, payload: MetricEventTypeMap[T])` — validates payload against the matching Zod schema (lazy lookup via a `Map<typeKey, ZodSchema>` populated at construction); on validation failure, logs via `services.logger.warn` and DOES NOT throw (the bus must not crash a probe). On success, calls `super.emit(type, payload)`.
- `subscribe<T extends keyof MetricEventTypeMap>(type: T, handler: (payload: MetricEventTypeMap[T]) => void): () => void` — wraps `super.on(type, handler)` and returns the unsubscribe function (matching `TypedEventEmitter` contract).
- `dispose()` — calls `super.removeAllListeners()` + clears the coalesce timer.

Internal coalescing for bridge forwarding (P-03.9):
- Maintain a `pendingSamples: MetricSample[]` array.
- When `emit('monitor:metric', sample)` fires, push the sample into `pendingSamples` AND start a `setTimeout(flushBatch, this.coalesceWindowMs)` if not already scheduled.
- `flushBatch()` posts a single `monitor:metrics:batch` envelope through `this.bridge?.send(...)` with all pending samples, then clears the array + timer.
- For high-importance non-sample events (`drift:detected`, `anomaly:detected`, `fleet:summary`), forward immediately to bridge — no coalescing.

Exhaustiveness: any internal `switch (event.type)` MUST end with `default: assertNever(event)` per P-03.8.
</action>

Append a final integration test to `MetricBus.test.ts` named `'Plan 03-01 vertical slice: emit → bridge → subscribe round-trip'`:

```typescript
it('Plan 03-01 vertical slice: emit -> bridge -> subscribe round-trip', () => {
  vi.useFakeTimers();
  const bridgeSendSpy = vi.fn();
  const bus = new MetricBus({ bridge: { send: bridgeSendSpy } as any, coalesceWindowMs: 250 });
  const samples: MetricSample[] = [];
  const unsubscribe = bus.subscribe('monitor:metric', (s) => samples.push(s));

  // Probe emits
  bus.emit('monitor:metric', { ts: new Date().toISOString(), seriesId: 'limits.api', orgId: 'org-1', value: 42 });
  bus.emit('monitor:metric', { ts: new Date().toISOString(), seriesId: 'limits.api', orgId: 'org-1', value: 43 });

  // Subscribers received synchronously
  expect(samples).toHaveLength(2);
  // Bridge has not yet fired (within coalesce window)
  expect(bridgeSendSpy).not.toHaveBeenCalled();

  // Coalesce window elapses
  vi.advanceTimersByTime(250);
  expect(bridgeSendSpy).toHaveBeenCalledOnce();
  expect(bridgeSendSpy.mock.calls[0][0]).toMatchObject({ type: 'monitor:metrics:batch', payload: { samples: expect.arrayContaining([expect.objectContaining({ value: 42 }), expect.objectContaining({ value: 43 })]) }});

  unsubscribe();
  bus.dispose();
});
```

This is the demoable proof that Plan 03-01 ships an end-to-end vertical slice — a test (or any future probe / panel) emits an event, in-process subscribers see it, and the bridge receives a coalesced batch. Phase 03's substrate is observable.
