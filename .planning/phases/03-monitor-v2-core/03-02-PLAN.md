# Plan 03-02: TimeSeriesStore (ring buffer + opt-in disk persist)

**Requirements covered:** MON-02 (TimeSeriesStore in-memory ring buffer with opt-in disk persistence; 7 day retention; 50 MB cap).

## Goal

Ship the time-series storage substrate so probes can record samples and downstream features (Anomaly engine, Report exporter, Drift v2) can query historical data — with bounded memory, opt-in disk persistence, and a demoable property test that pushes 50,000 random samples through and asserts the ring-buffer + LRU caps hold.

## Depends on

- **03-01** ships `MetricSample` + `MetricEvent` types from `@sandforge/shared/monitor`. This plan imports `MetricSample` to type the store contents.

No file overlap with sibling Wave 1 plans:
- **03-01** writes `MetricBus.ts` and shared `MetricEvent.ts` — does NOT touch `TimeSeriesStore.ts` or any persistence code.
- **03-03** writes `MonitorRegistry.ts` and adapts existing tracker files — uses `TimeSeriesStore` via `monitorOrchestrator.timeSeriesStore.record(sample)` but does not edit it.

## Non-goals

- **Adding `mnemonist` or any ring-buffer npm package.** RESEARCH §1 explicitly forbids — own ring buffer is < 50 LOC and matches existing inline FIFO patterns in `LimitsTracker` / `TrendStorage`.
- **Streaming time-series to disk on every record() call.** Default OFF per D-03-2; opt-in via setting. When on, batch-write every 5 min — same cadence as `TrendStorage`.
- **Querying Setup Audit Trail or any historical Salesforce data.** This store is for probe-emitted samples ONLY. Snapshots remain in `SnapshotManager` (Compare module, untouched here).
- **A new persistence format** (Parquet, SQLite, gzip frames). JSON via existing `ConfigStore` (RESEARCH §2 "Persistence pattern"). Same caps as `TrendStorage`: 500 KB / 7 days / 15-min rate-limit per org.
- **Cross-org aggregation queries.** This is a `Map<orgId, Map<seriesId, RingBuffer>>` — queries are scoped per `(orgId, seriesId)`. Multi-org fleet aggregation is Plan 03-07.

## Pitfalls mitigated (RESEARCH §3)

- **P-03.1 (Memory blow-up at 5+ orgs)** — per-series capacity derivation + LRU eviction at 50 MB.
- **P-03.10 (Persistence rehydration race)** — `await store.rehydrate()` before `MonitorRegistry.start()`.

Create `packages/extension/src/modules/monitor/RingBuffer.ts`. Pure data structure, no Salesforce concerns. Must NOT depend on `mnemonist`.

Class shape:
```typescript
export class RingBuffer<T> {
  private buffer: T[];
  private head = 0;          // next write index
  private size = 0;          // current count

  constructor(public readonly capacity: number) {
    if (capacity <= 0 || !Number.isFinite(capacity)) throw new Error(...)
    this.buffer = new Array(capacity);
  }

  push(value: T): T | undefined { /* returns evicted T if full */ }
  toArray(): T[]                  /* in chronological insertion order */
  range(predicate: (t: T) => boolean): T[]
  get length(): number            /* === size */
  clear(): void
}
```

Implementation:
- `push`: capture `evicted = (size === capacity) ? buffer[head] : undefined`, write `buffer[head] = value`, advance `head = (head + 1) % capacity`, bump `size = Math.min(size + 1, capacity)`. Return `evicted`.
- `toArray`: when `size < capacity`, slice `buffer.slice(0, size)`. When full, concat `buffer.slice(head)` + `buffer.slice(0, head)` for chronological order.
- `range`: filter `toArray()` by predicate; intentionally simple — caller-side time-window filters compose cleanly on top.
- `clear`: reset `head = 0`, `size = 0`, fill buffer with `undefined` to release retained refs (V8 GC hint).

NO dependencies beyond the class itself.
</action>

- `private lruOrder: string[]` — `(orgId,seriesId)` key in LRU order; updated on every record/query.
- `private estimatedBytes = 0` — tracked incrementally in record/evict.

Public API:
- `record(sample: MetricSample, options?: { intervalMs?: number }): void`

  - Push sample; if eviction, decrement `estimatedBytes -= APPROX_BYTES_PER_SAMPLE` (96).
  - If `estimatedBytes > maxBytes`, evict oldest LRU `(orgId,seriesId)` partitions until under cap.
  - Update LRU order.
- `query(orgId: string, seriesId: string, fromMs?: number, toMs?: number): MetricSample[]`
  - Returns samples within `[fromMs, toMs]` (defaults: oldest in series → now()).
  - Updates LRU.
- `getStats(): { totalSamples, estimatedBytes, perOrgBytes: Record<string, number>, perSeries: number }` — for the 5-min watchpoint logger (P-03.1).
- `clear(orgId?: string): void` — clear single org or all.
- `rehydrate(): Promise<void>` — see next task.
- `flush(): Promise<void>` — see next task.

Constants exported from this file:
- `APPROX_BYTES_PER_SAMPLE = 96`
- `DEFAULT_RETENTION_DAYS = 7`
- `DEFAULT_MAX_BYTES = 50 * 1024 * 1024`
- `PERSIST_FLUSH_INTERVAL_MS = 5 * 60 * 1000` (matches TrendStorage cadence)

The store does NOT subscribe to MetricBus directly — Plan 03-03 wires `metricBus.subscribe('monitor:metric', s => store.record(s))` in the registry. Decoupled.
