# Plan 03-03: MonitorProbe Refactor + describe-cache fold-in

**Requirements covered:** MON-03 (refactor existing trackers into `MonitorProbe` implementations driven by a single-tick `MonitorRegistry`).

## Goal

Refactor the 8 existing trackers (LimitsTracker, JobMonitor, ApexLogAnalyzer, SandboxRefreshTracker, ErrorLogMonitor, UserSessionMonitor, HealthCheck, GovernanceEngine) into thin `MonitorProbe` adapters; introduce a single-tick `MonitorRegistry` scheduler driven by ONE `setInterval` per org; fold in the target-org `describeFields` cache (audit Perf #1) since the Probe scheduler is the natural seam. Demoable: a Vitest test with a fake probe whose `run()` takes 5 seconds runs through 10 ticks and shows zero overlapping invocations + zero scheduling drift.

## Depends on

- **03-01** ships `MetricBus` + `MetricSample` type — every probe emits samples through `metricBus.emit('monitor:metric', sample)`.
- **03-02** ships `TimeSeriesStore` — `MonitorRegistry` subscribes the store to the bus.

No file overlap with sibling plans:
- **03-01** wrote `MetricBus.ts` + shared types — this plan imports them.
- **03-02** wrote `TimeSeriesStore.ts` + `RingBuffer.ts` — this plan only references them through `MonitorOrchestrator`.
- **Wave 2** plans (03-04 — 03-07) consume probes through `MonitorRegistry.register(probe)` but don't edit the registry or any probe wrapper.

## Non-goals

- **Rewriting tracker computation logic.** Each tracker's `fetch()` body is preserved verbatim — the probe wrapper is a thin shell that calls `fetch()` and maps the result into `MetricSample[]`. RESEARCH §2 ("Existing trackers") explicitly states pre-existing tests stay green.
- **Replacing `setInterval` with worker_threads or BroadcastChannel.** Single-tick `setInterval` is sufficient; complexity not justified.
- **Implementing `monitor:visibility` end-to-end** — Plan 03-07 owns the WebView side (`document.hidden` listener + posting the message). This plan owns the EXTENSION side (subscribing to that message + gating low-priority probes).
- **Fixing audit C5 (BulkApiManager singleton) or C1 (aiProvider stub)** — those are Phase 06 (CONTEXT D-03-9, RESEARCH §4 cross-references).
- **Fixing audit M5 in extension state** — RESEARCH §3 P-03.7 says M5 applies only to WebView Zustand stores, NOT to the extension-side `Map<probeId, ...>` in `MonitorRegistry` which IS the right structure here.
- **Adding a new persistence path for probe configuration.** Probes register themselves in `MonitorOrchestrator.start()` programmatically — no user-facing probe-list editor in v1.3.0.

## Pitfalls mitigated (RESEARCH §3)

- **P-03.6 (Probe scheduling drift / overlap)** — per-probe in-flight gate, drift-accounting via lastFinishedAt, hard 30s timeout, visibility-gated tick rate.
- **P-03.7 — audit Perf #1 (describe cache miss)** — owned by this plan; new `DescribeCache` adapter wraps `salesforce.describeFields`.
- **P-03.7 — audit M1 (visibility-gated polling)** — extension-side gate; Plan 03-07 owns the webview-side message.

Class shape:
```typescript
export interface MonitorRegistryDeps {
  metricBus: MetricBus;
  timeSeriesStore: TimeSeriesStore;
  logger?: Logger;
  telemetry?: TelemetryService;
  now?: () => number;
}

export class MonitorRegistry {
  private probes = new Map<string, MonitorProbe>();
  private activeOrgs = new Set<string>();    // mirrors MonitorOrchestrator pattern
  private nextRunAt = new Map<string, number>();  // key = `${orgId}:${probeId}`
  private inFlight = new Map<string, Promise<void>>();  // P-03.6
  private tickTimer?: ReturnType<typeof setInterval>;
  private documentHidden = false;            // updated via setVisibility(true|false)

  constructor(private deps: MonitorRegistryDeps) {
    deps.metricBus.subscribe('monitor:metric', (s) => deps.timeSeriesStore.record(s));
  }

  register(probe: MonitorProbe): void { ... }
  unregister(probeId: string): void { ... }
  startOrg(orgId: string): void { ... }
  stopOrg(orgId: string): void { ... }
  setVisibility(hidden: boolean): void { this.documentHidden = hidden; }   /* audit M1 */
  dispose(): void { ... }
  getStats(): { probeCount, activeOrgCount, inFlightCount } { ... }

  private start(): void {
    if (this.tickTimer) return;
    this.tickTimer = setInterval(() => this.tick(), this.computeTickRate());
  }

  private computeTickRate(): number {
    // P-03.6: tick at min(probe.intervalMs)/4 clamped [1s, 10s]; if hidden, force 30s.
    if (this.documentHidden) return 30_000;
    const minInterval = Math.min(...[...this.probes.values()].map(p => p.intervalMs), Infinity);
    return Math.max(1_000, Math.min(10_000, Math.floor(minInterval / 4)));
  }

  private tick(): void {
    const now = this.deps.now?.() ?? Date.now();
    for (const orgId of this.activeOrgs) {
      for (const probe of this.probes.values()) {
        // Skip low-priority probes when hidden (audit M1, P-03.7)
        if (this.documentHidden && probe.priority === 'low') continue;
        const key = `${orgId}:${probe.id}`;
        if (this.inFlight.has(key)) continue;     // P-03.6 in-flight gate
        const due = this.nextRunAt.get(key) ?? 0;
        if (now < due) continue;
        this.dispatch(probe, orgId, key);
      }
    }
  }

  private async dispatch(probe: MonitorProbe, orgId: string, key: string): Promise<void> {
    const startedAt = Date.now();
    const promise = (async () => {
      try {
        const samples = await Promise.race([
          probe.run(orgId),
          new Promise<MetricSample[]>((_, rej) =>
            setTimeout(() => rej(new Error(`Probe ${probe.id} timed out after ${PROBE_HARD_TIMEOUT_MS}ms`)), PROBE_HARD_TIMEOUT_MS)),
        ]);
        for (const s of samples) this.deps.metricBus.emit('monitor:metric', s);
      } catch (err) {
        this.deps.logger?.warn(`[MonitorRegistry] Probe ${probe.id} failed for ${orgId}: ${(err as Error).message}`);
        this.deps.telemetry?.addBreadcrumb({ category: 'monitor', message: 'probe-failed', data: { probeId: probe.id, orgId } });
      } finally {
        const finishedAt = Date.now();
        // P-03.6: drift accounting — schedule based on finishedAt, not startedAt
        this.nextRunAt.set(key, finishedAt + probe.intervalMs);
        this.inFlight.delete(key);
      }
    })();
    this.inFlight.set(key, promise);
  }
}
```

Constants: import `PROBE_HARD_TIMEOUT_MS` from `MonitorProbe.ts`.
