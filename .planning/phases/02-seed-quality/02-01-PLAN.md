# Plan 1: Locale-aware Faker, Geo-coherent Addresses, Realistic Ranges

## Objective

Upgrade the Seed data generation pipeline so that FakerFallback produces locale-appropriate data (SQUAL-01), address fields use coherent city+state+country tuples (SQUAL-02), and currency/date fields use context-aware ranges per object type (SQUAL-05). This makes seeded data look realistic instead of random English-only gibberish.

## Context

**Current state:** FakerFallback.ts uses hardcoded English-only arrays (FIRST_NAMES, LAST_NAMES, CITIES, etc.) and generates addresses by independently picking from separate arrays (city from one list, country from another -- producing "Paris, Texas, Japan" combinations). Number ranges default to 0-1000 regardless of field context.

**Key types:** `FieldRuleConfig` already has a `fakerLocale?: string` field (in seed.types.ts:55) that is not used anywhere in FakerFallback. The `FakerFallback.generate()` method receives `FieldRule[]` where each rule has `config.fakerLocale`.

**Approach:**
1. Create `LocaleData.ts` -- a static dataset module with names, cities, companies, phone formats, and zip patterns for 6 locales (en_US + the 5 required: fr_FR, de_DE, es_ES, ja_JP, pt_BR).
2. Create `GeoCoherentGenerator.ts` -- produces tuples of (city, state, country, zipCode) that are geographically consistent, per locale.
3. Create `ContextualRanges.ts` -- maps object+field patterns to realistic min/max ranges (Opportunity.Amount: 5000-500000, Case.Priority: n/a, CloseDate: +30 to +180 days, etc.).
4. Modify `FakerFallback` to accept a locale parameter and delegate to LocaleData.
5. Modify `SmartFieldGenerator.suggestForField` to inject geo-coherent config for address fields and contextual ranges for currency/date fields.

**Constraints:** TypeScript strict (no `any`), JSDoc on all public methods, Winston logger (no console.log), co-located .test.ts files.

   - de_DE: `{ city: 'Berlin', state: 'Berlin', country: 'Germany', zipCode: '10115' }`

   - `constructor(locale?: string)` -- defaults to 'en_US'

   - `getZipCode(index: number): string` -- returns zipCode from the tuple

   - `Opportunity.Amount` -> `{ min: 5000, max: 500000, decimals: 2 }`
   - `Opportunity.ExpectedRevenue` -> `{ min: 2500, max: 250000, decimals: 2 }`
   - `OpportunityLineItem.UnitPrice` -> `{ min: 50, max: 5000, decimals: 2 }`
   - `OpportunityLineItem.TotalPrice` -> `{ min: 100, max: 50000, decimals: 2 }`
   - `Product2.UnitPrice` (or any `*Price*`) -> `{ min: 10, max: 10000, decimals: 2 }`
   - `Invoice.TotalAmount` (or any `*Amount*`, `*Total*`) -> `{ min: 100, max: 100000, decimals: 2 }`
   - `*.AnnualRevenue` -> `{ min: 100000, max: 10000000, decimals: 0 }`
   - `*.NumberOfEmployees` -> `{ min: 1, max: 50000, decimals: 0 }`
   - `*.Quantity*` -> `{ min: 1, max: 1000, decimals: 0 }`
   - `*.Discount*` (or `*.Percent*`) -> `{ min: 0, max: 100, decimals: 1 }`
   - Fallback for unmatched currency fields: `{ min: 100, max: 50000, decimals: 2 }`

   Use a priority system: exact object.field match first, then field-name pattern match, then fallback.

4. A `getDateRange(objectName: string, fieldName: string): DateRange` function:
   - `Opportunity.CloseDate` -> `{ minDaysFromNow: 30, maxDaysFromNow: 180 }`
   - `*.StartDate` -> `{ minDaysFromNow: -30, maxDaysFromNow: 90 }`
   - `*.EndDate` -> `{ minDaysFromNow: 30, maxDaysFromNow: 365 }`
   - `*.Birthdate` -> `{ minDaysFromNow: -25550, maxDaysFromNow: -6570 }` (18-70 years old)
   - `*.CreatedDate`, `*.LastModifiedDate` -> `{ minDaysFromNow: -365, maxDaysFromNow: 0 }`
   - `*.DueDate` -> `{ minDaysFromNow: 7, maxDaysFromNow: 90 }`
   - Fallback for unmatched date fields: `{ minDaysFromNow: -90, maxDaysFromNow: 90 }`

5. A `generateDateFromRange(range: DateRange, index: number): string` helper that produces an ISO date string (YYYY-MM-DD) deterministically spread across the range.

JSDoc on all exports.

- `getDateRange('Contact', 'Birthdate')` returns past dates (maxDays < 0)
- `generateDateFromRange` produces valid ISO date strings within range
