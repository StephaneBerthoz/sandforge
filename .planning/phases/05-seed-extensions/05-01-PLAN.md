# Plan 01: CSV Import Backend

## Objective

Build the backend services for CSV import into Salesforce: a CsvImportService that coordinates parsing and type conversion, a CsvFieldMapper that auto-maps CSV columns to Salesforce fields using describe metadata, and a CsvValidator that catches type mismatches, missing required fields, length violations, and duplicate external IDs before execution. Wire these into SeedOpsHandler via new `seed:csv:execute` and `seed:csv:validate` message types. This enables the WebView (Plan 03) to send CSV data for validated insertion.

## Context

- **Papaparse is already installed** in the webview package. CSV parsing in the WebView will happen there (Plan 03). This plan handles the EXTENSION side: receiving already-parsed rows (array of objects) with column mappings, validating them against Salesforce metadata, and inserting via the existing BulkApiManager pipeline.
- **SeedOpsHandler** (`packages/extension/src/bridge/handlers/SeedOpsHandler.ts`) is the existing handler for seed messages. It already has an `insertFn` factory (lines ~303-350) that switches between Bulk API and REST based on record count. CSV execution must reuse this exact pattern.
- **Field metadata** comes from the existing `seed:describe-object` handler which returns field metadata including `createable`, `type`, `length`, `nillable`, `picklistValues`. The CsvFieldMapper and CsvValidator use this metadata.
- **BOM handling**: The WebView will strip BOM before sending data. The backend should still handle it defensively.
- **Type conversion**: CSV data arrives as strings. CsvImportService converts values based on the Salesforce field type from the column mapping (Number, Currency, Percent -> parseFloat; Boolean -> true/false; Date -> ISO format).
- **Messages types**: Follow the existing pattern in `messages.types.ts`. All seed messages use the `seed:` prefix. Add `seed:csv:execute` (sends mapped rows + target object + orgId) and `seed:csv:validate` (sends mapped rows, returns validation errors).

<action>
**CsvFieldMapper** (`CsvFieldMapper.ts`):
- Export class `CsvFieldMapper`.
- Method `autoMapColumns(csvHeaders: string[], describeFields: DescribeField[]): CsvColumnMapping[]`:
  - Filter describeFields to only `createable === true`.
  - For each CSV header, attempt matching against field `name` and `label`:
    1. Exact match (case-insensitive).
    2. Underscore/space-tolerant match: normalize both sides by removing underscores, spaces, and `__c` suffix, then compare lowercase.
  - Return array of `CsvColumnMapping` for matched columns. Unmatched columns return with `sfFieldApiName: ''` (unmapped).
  - MUST exclude non-createable fields: `Id`, `CreatedDate`, `CreatedById`, `LastModifiedDate`, `LastModifiedById`, `SystemModstamp`, `IsDeleted`.
- Method `convertValue(value: string, sfFieldType: string): unknown`:
  - `'double' | 'currency' | 'percent' | 'int'` -> `parseFloat(value)` or `parseInt(value)`, return `null` if NaN.
  - `'boolean'` -> `value.toLowerCase() === 'true' || value === '1'`.
  - `'date'` -> validate ISO date format, return string.
  - `'datetime'` -> validate ISO datetime, return string.
  - All others -> return string as-is.
  - Empty string -> return `null`.
- JSDoc on class and both methods.

**CsvValidator** (`CsvValidator.ts`):
- Export class `CsvValidator`.
- Method `validate(records: Record<string, string>[], columnMappings: CsvColumnMapping[], describeFields: DescribeField[]): CsvValidationResult`:
  - For each record (row), for each mapped column:
    1. **Type mismatch**: If field type is numeric and value is not parseable as number.
    2. **Missing required**: If field is `nillable === false` and `defaultValue === null` and value is empty.
    3. **Length exceeded**: If field has `length > 0` and `value.length > field.length`.
    4. **Invalid picklist**: If field type is `picklist` and value not in `picklistValues[].value` (case-sensitive).
  - **Duplicate external ID**: If `externalIdField` is set, check for duplicate values in that column across all rows.
  - Return `CsvValidationResult` with all errors collected. `valid` is `true` only if `errors.length === 0`.
  - Cap error collection at 100 errors (stop scanning after 100 to avoid memory issues on large files).
- JSDoc on class and method.

**Tests** -- at least 4 test cases each:
- CsvFieldMapper.test.ts: exact match, case-insensitive match, underscore-tolerant match, non-createable field exclusion, convertValue for each type.
- CsvValidator.test.ts: valid data returns no errors, type mismatch detected, missing required detected, length exceeded detected, duplicate external ID detected, error cap at 100.
</action>
