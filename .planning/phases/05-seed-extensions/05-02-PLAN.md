# Plan 02: Clone Backend

## Objective

Build the entire Clone backend: CloneRecordFetcher queries records from a source org using cursor-based pagination, CloneReferenceLinker topologically sorts objects for parent-before-child insertion, and CloneOrchestrator coordinates the full pipeline (fetch -> remap -> insert) with two-pass logic for self-referential lookups. A new CloneOpsHandler exposes this to the WebView. This is the most net-new feature in Phase 05 -- no existing Clone backend exists.

## Context

- **AutopilotExecutor** (`packages/extension/src/modules/autopilot/AutopilotExecutor.ts`) is the closest existing pattern. It does query -> anonymize -> remap -> insert wave-by-wave. Clone is essentially the same minus anonymization. Study its wave execution, QueryFn/InsertFn types, and how it calls RecordIdRemapper.
- **RecordIdRemapper** (`packages/extension/src/modules/autopilot/RecordIdRemapper.ts`): Reuse directly. Maps `objectApiName -> Map<sourceId, targetId>`. Methods: `registerMappings(objectApiName, sourceIds, targetIds)`, `remapRecords(records, edges, objectApiName)`, `getTargetId(objectApiName, sourceId)`.
- **AutopilotEdge** type: `{ from: string; to: string; field: string; }` -- represents a lookup relationship. When `from === to`, it's self-referential.
- **getJsforceConnection**: Already supports any orgId via OrgRegistry + ConnectionPool. Clone calls it twice: once for sourceOrgId, once for targetOrgId.
- **Pitfall -- queryMore**: SOQL OFFSET is limited to 2000. Use `conn.query(soql)` + `conn.queryMore(nextRecordsUrl)` for cursor-based pagination. jsforce v2 supports this natively.
- **Pitfall -- self-referential**: Account.ParentId creates a cycle within the same object. Two-pass: (1) insert with self-ref fields set to NULL, (2) UPDATE with remapped IDs after all records inserted.
- **ReferenceLinker** in seed module uses `SeedObjectConfig.fieldRules` for topo sort. Clone uses `AutopilotEdge[]` instead. Create a new `CloneReferenceLinker` that accepts edges and produces the sorted order using Kahn's algorithm (same as existing ReferenceLinker but different input type).
- **BulkApiExecutor + BulkApiManager**: Reuse for insertion. Follow the same `insertFn` factory pattern from SeedOpsHandler.
- **Message types note**: Plan 01 also modifies `messages.types.ts`. Since both plans are Wave 1, they modify different sections of this file. Plan 01 adds `seed:csv:*` types, this plan adds `seed:clone:*` types. The executor must be careful to merge, not overwrite. To minimize conflict, this plan adds clone types in a clearly separate section/block.

<action>
**CloneRecordFetcher** (`CloneRecordFetcher.ts`):
- Export class `CloneRecordFetcher`.
- Constructor takes `deps: { logger: Logger }`.
- Method `fetchRecords(conn: Connection, objectApiName: string, whereClause?: string): Promise<Record<string, unknown>[]>`:
  - Build SOQL: `SELECT <all createable fields + Id + lookup fields> FROM ${objectApiName}` + optional `WHERE ${whereClause}`.
  - To get field list, call `conn.describe(objectApiName)` and collect fields where `createable === true` OR field is a lookup (type `reference`) needed for remapping. Always include `Id`.
  - Execute `conn.query(soql)`.
  - Use cursor-based pagination: while `result.done === false`, call `conn.queryMore(result.nextRecordsUrl)` and append records.
  - Return all records as array.
  - Log record count at info level.
- Method `countRecords(conn: Connection, objectApiName: string, whereClause?: string): Promise<number>`:
  - Execute `SELECT COUNT() FROM ${objectApiName}` + optional WHERE.
  - Return count.
- Method `fetchSample(conn: Connection, objectApiName: string, limit: number, whereClause?: string): Promise<Record<string, unknown>[]>`:
  - Same as fetchRecords but with `LIMIT ${limit}` appended. No pagination needed.
- JSDoc on class and all methods.

**CloneReferenceLinker** (`CloneReferenceLinker.ts`):
- Export class `CloneReferenceLinker`.
- Method `resolveInsertOrder(objects: string[], edges: AutopilotEdge[]): string[]`:
  - Implement Kahn's algorithm for topological sort.
  - `edges` define lookup relationships: `edge.from` has a lookup field `edge.field` pointing to `edge.to`.
  - Objects with no incoming edges (no parent dependencies) go first.
  - If a cycle is detected (remaining nodes but no zero-in-degree nodes), throw an error listing the cycle participants.
  - Self-referential edges (where `from === to`) do NOT count as dependencies for ordering purposes (they are handled by two-pass insert).
  - Return sorted array of object API names.
- Method `detectSelfReferentialEdges(edges: AutopilotEdge[]): AutopilotEdge[]`:
  - Return edges where `edge.from === edge.to`.
- Method `buildEdgesFromDescribe(objectApiNames: string[], describeResults: Map<string, DescribeSObjectResult>): AutopilotEdge[]`:
  - For each object, iterate its fields. For fields where `type === 'reference'` and `referenceTo` includes an object in `objectApiNames`, create an `AutopilotEdge`.
  - Return all edges.
- JSDoc on class and all methods.

**Tests**:

- CloneReferenceLinker.test.ts: linear chain (A -> B -> C) sorted correctly, self-referential edge ignored for ordering, cycle detection throws error, buildEdgesFromDescribe creates correct edges, empty input returns empty array.
</action>

<action>
**CloneOrchestrator** (`CloneOrchestrator.ts`):
- Export class `CloneOrchestrator`.
- Constructor takes `deps: { logger: Logger; fetcher: CloneRecordFetcher; linker: CloneReferenceLinker; remapper: RecordIdRemapper; }`.
- Import `RecordIdRemapper` from `../../modules/autopilot/RecordIdRemapper.js`.
- Method `execute(sourceConn: Connection, targetConn: Connection, config: CloneConfig, insertFn: InsertFn, onProgress: ProgressCallback): Promise<CloneExecutionResult>`:
  - Step 1: Describe all objects on source org. Build edges via `linker.buildEdgesFromDescribe()`.
  - Step 2: Resolve insert order via `linker.resolveInsertOrder()`.
  - Step 3: Detect self-referential edges via `linker.detectSelfReferentialEdges()`.
  - Step 4: For each object in insert order:
    a. Fetch records from source org via `fetcher.fetchRecords()`.
    b. Remap lookup fields to target org IDs via `remapper.remapRecords()`. For the first object in the chain, no remapping needed (no parent dependencies yet).
    c. For self-referential fields: set them to `null` before insert (store original values).
    d. Insert into target org via `insertFn(targetConn, objectApiName, records)`.
    e. Register ID mappings via `remapper.registerMappings(objectApiName, sourceIds, targetIds)`.
    f. Report progress via `onProgress`.
  - Step 5: Self-referential UPDATE pass: for objects with self-referential edges, build UPDATE records using remapped self-ref IDs, execute update via `targetConn.sobject(objectApiName).update(records)`.
  - Step 6: Build and return `CloneExecutionResult`.
  - Handle errors per-object (don't abort entire clone on single object failure).
- Type `InsertFn`: `(conn: Connection, objectApiName: string, records: Record<string, unknown>[]) => Promise<{ sourceIds: string[]; successIds: string[]; failedIds: Array<{ id: string; message: string }> }>`. Match the pattern from AutopilotExecutor.
- Type `ProgressCallback`: `(objectApiName: string, phase: 'fetching' | 'inserting' | 'updating', current: number, total: number) => void`.
- JSDoc on class and method.

**CloneOpsHandler** (`CloneOpsHandler.ts`):
- Export class `CloneOpsHandler` implementing `DomainHandler`.
- Handle message types: `seed:clone:execute`, `seed:clone:preview`, `seed:clone:describe-source`.
- `CLONE_TYPES` Set with all three message types.
- `canHandle(type: string)`: return `CLONE_TYPES.has(type)`.
- `handle(message, deps)`:
  - `seed:clone:describe-source`: Call `getJsforceConnection(sourceOrgId)`, then `conn.describeGlobal()`, return filtered list of standard + custom objects (same pattern as seed:describe-global in SeedOpsHandler).
  - `seed:clone:preview`: Call `getJsforceConnection(sourceOrgId)`. For each object in config, call `fetcher.countRecords()` and `fetcher.fetchSample(conn, obj, 5)`. Build edges, resolve insert order. Return `ClonePreviewResult`.
  - `seed:clone:execute`: Call `getJsforceConnection` for BOTH sourceOrgId and targetOrgId. Build `insertFn` using the same BulkApiManager/REST threshold pattern from SeedOpsHandler. Send `operationStarted`. Create CloneOrchestrator and call `execute()`, forwarding progress via `sendOperationProgress`. On completion send `operationCompleted` with `CloneExecutionResult`. On failure send `operationFailed`.
- Register CloneOpsHandler in the handler registry (same file where SeedOpsHandler is registered -- check `packages/extension/src/bridge/MessageRouter.ts` or equivalent).

- CloneOpsHandler.test.ts: clone:describe-source returns filtered objects, clone:preview returns counts and insert order, clone:execute calls orchestrator and sends progress events. Mock connections and fetcher.
