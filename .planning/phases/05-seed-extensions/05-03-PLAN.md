# Plan 03: CSV Import UI

## Objective

Build the complete CSV import user interface: a reusable FileDropZone component for drag-and-drop file selection, a CsvUploadWizard with 4 steps (upload, map columns, validate, execute), column auto-mapping using Salesforce describe metadata, inline validation error display, and execution status tracking. Integrate this into SeedPage as one of three seed modes. This plan depends on Plan 01 (CSV backend types and handlers).

## Context

- **Papaparse** is installed in the webview package (`@types/papaparse` too). Use it for client-side parsing with `dynamicTyping: false` (Pitfall 1 from research). Strip BOM before parsing (Pitfall 2). For preview, use `preview: 10` option. For full parse of large files, use `worker: true`.
- **File reading in WebView**: Use standard `<input type="file" accept=".csv">` and HTML5 drag-and-drop events (`onDragOver`, `onDrop`). Do NOT use VSCode workspace APIs from WebView.
- **Column mapping UI**: After parsing, show a table where each row is a CSV column. Left column shows CSV header, right column is a Select dropdown populated with createable Salesforce fields from `seed:describe-object`. Auto-match is done client-side using the same logic as CsvFieldMapper (case-insensitive, underscore-tolerant). User can override any mapping.
- **Validation**: Send mapped records to extension via `seed:csv:validate` message. Display returned `CsvValidationError[]` inline, grouped by error type with row/column references.
- **Execution**: Send via `seed:csv:execute`. Reuse the same progress/completion event pattern as existing seed execution (listen for `operation:started`, `operation:progress`, `operation:completed`, `operation:failed`).
- **SeedPage integration**: Currently SeedPage shows TemplateGallery + SeedWizard. Add a mode selector at the top: "AI Generate" (existing), "CSV Upload" (new), "Clone from Org" (Plan 04). Mode selector should be card-based (3 cards with icon + description). When CSV is selected, show CsvUploadWizard instead of the existing wizard.
- **Existing components to reuse**: `Select`, `Button`, `Card`, `Badge`, `DataTable`, `Skeleton`, `ErrorBanner`, `EmptyState`, `PageHeader`, `OrgBadge`.
- **State management**: Create `useCsvImport` hook following the composable pattern of `useSeedWizardState` (sub-hooks). State: `file: File | null`, `parsedData: Record<string, string>[]`, `headers: string[]`, `columnMappings: CsvColumnMapping[]`, `validationResult: CsvValidationResult | null`, `executionStatus`, `targetOrg`, `targetObject`.
- **i18n**: All visible strings via `t('seed.csv.*')`. Add keys to both en.json and fr.json.

**FileDropZone** (`FileDropZone.tsx`):
- Export `FileDropZone` functional component.
- Props: `{ onFileSelected: (file: File) => void; accept?: string; maxSizeMB?: number; disabled?: boolean; }`.
- Renders a bordered dashed div (Tailwind: `border-2 border-dashed rounded-lg p-8 text-center`).
- Shows upload icon, "Drag & drop your CSV file here" text, and "or browse files" button.
- Implements HTML5 drag-and-drop: `onDragOver` (prevent default, set hover state), `onDragLeave`, `onDrop` (extract file from `e.dataTransfer.files[0]`).
- Contains a hidden `<input type="file" accept={accept}>` triggered by the browse button.
- On hover state, change border color to primary (visual feedback).
- Validate file size against `maxSizeMB` (default 50). Show error via ErrorBanner if exceeded.
- After file selected (either drop or browse), call `onFileSelected(file)`.
- All text via `t('seed.csv.dropzone.*')`.
- JSDoc on component.

**useCsvImport** (`useCsvImport.ts`):
- Export hook `useCsvImport(t: TFunction)`.
- State managed via `useState`:
  - `file: File | null`
  - `headers: string[]`
  - `parsedRows: Record<string, string>[]`
  - `previewRows: Record<string, string>[]` (first 10)
  - `columnMappings: CsvColumnMapping[]`
  - `targetOrgId: string`
  - `targetObjectApiName: string`
  - `describeFields: DescribeField[]` (from seed:describe-object)
  - `validationResult: CsvValidationResult | null`
  - `executionStatus: 'idle' | 'validating' | 'executing' | 'complete' | 'error'`
  - `executionResult: any` (from operation:completed)
  - `step: 'upload' | 'map' | 'validate' | 'execute'`
- Methods:
  - `handleFileSelected(file: File)`: Use papaparse with `{ header: true, dynamicTyping: false, preview: 11, skipEmptyLines: true }`. Strip BOM from the raw text first (`text.replace(/^\uFEFF/, '')`). Actually, use `Papa.parse(file, { ... })` which reads the File directly. For preview, parse with `preview: 10`. Store headers and previewRows. For full data, parse without preview limit (use `worker: true` for large files). Advance step to 'map'.
  - `handleObjectSelected(orgId: string, objectApiName: string)`: Send `seed:describe-object` message, store result in describeFields. Auto-map columns using client-side matching (same logic as CsvFieldMapper: case-insensitive, underscore-tolerant, createable-only). Store mappings.
  - `handleMappingChange(csvHeader: string, sfFieldApiName: string)`: Update one mapping.
  - `handleValidate()`: Send `seed:csv:validate` message with records + mappings. Store result. If valid, advance to 'execute' step.
  - `handleExecute()`: Send `seed:csv:execute` message. Listen for operation events. Update executionStatus.
  - `reset()`: Clear all state back to initial.
- Return all state + methods.

**Tests**:
- FileDropZone.test.tsx: renders drop zone with text, calls onFileSelected on file input change, shows error for oversized file, visual hover state on dragover.
- useCsvImport.test.ts: handleFileSelected parses CSV and sets headers/previewRows, handleMappingChange updates mapping, reset clears all state. Mock papaparse and postMessage.
