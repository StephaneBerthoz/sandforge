# Migration

Import an existing SFDMU `export.json`, with the `FieldMapping.csv` and `ValueMapping.csv` beside it, into a Sync configuration. Importing reads the files and changes nothing in any org. A file is taken as SFDMU's own format defines it (its [`export.schema.json`](https://github.com/forcedotcom/SFDX-Data-Move-Utility/blob/master/schemas/export.schema.json)), and what Sync will not do as SFDMU would is listed on the page, object by object, under **What Sync will not do as SFDMU would**, above the save. Under **Run it from Sync**, pick the two orgs, leave **Neutralize emails and phone numbers** ticked or untick it, then **Save as a Sync configuration** and **Open in Sync**: Sync's Execute step says what each object does, simulates it, runs it, and its results say what it created and can remove it. A CSV file of records is not a migration definition: Seed's **CSV Upload** loads its rows.

## How to

1. Press Browse… and pick your SFDMU export.json, or paste its absolute path in File path.
2. Press Import: SandForge reads the file and writes nothing to any org.
3. Under Object Set, check each object's operation, External ID, batch size and WHERE clause.
4. Pick the Source org and the Target org, name it, and press Save as a Sync configuration.
5. Press Open in Sync: Simulate checks it there, and Run the sync writes it.

**Tip:** A CSV file of records goes to Seed's CSV Upload, which loads its rows. Only Sync writes, once Production Guard has judged the run.

## What the import carries

- Each object of the export becomes an object of the Sync configuration, in the order of the file, the objects of `objectSets` after those of `objects`, but for its deletes: SFDMU deletes before it writes, the last object listed first, or in the order of the file under `keepObjectOrderWhileExecute`, so each set's `Delete` and `HardDelete` objects go first, in that order. Listed Account then Case, the cases are deleted before the accounts they hold up. Its name comes from the FROM of its `query`, as in SFDMU, whatever the query's layout, case or alias; `name`, or `objectName`, counts only where no FROM can be read. An entry with no object to read, in its query, under `name` or under `objectName`, is refused, and nothing of the file is imported
- The `query` itself is not run. Sync reads every field the source org's describe lists, not the field list of the export's `query`, so the query's WHERE filter and ORDER BY are carried over as the object's filter and order, without the alias, and its operation and External ID come from the object's keys. A `where` key, which SFDMU does not read, counts only for a query with no WHERE; beside one, it is named and not read. To leave a field out, add it to `excludedFields`
- Under `useFieldMapping`, as in SFDMU, a `fieldMapping` and the rows of `FieldMapping.csv` for the object are read, the export's own entries over the file's. With the flag off or absent SFDMU ignores them, and so does the import, which says so
- A `fieldMapping` renames its field and that field alone: the source field goes under the target's name, and every other field of the object is copied under its own name, as read. An export that maps `BillingCity` onto `ShippingCity` writes the billing city into ShippingCity and the account's other fields as the source holds them; a mapping does not narrow the write to the mapped fields
- A `targetObject` that sends an object to another object, in the export or in `FieldMapping.csv`, is refused, and nothing of the export is imported: Sync writes an object to the same object in the target org, so the import names each object, where the export sends it and its field mappings, as `Account → Lead (Name → Company)`, for you to take those entries or those objects out of the file. With `useFieldMapping` off it is ignored, as SFDMU ignores it. A `targetObject` that names the object itself changes nothing, and an object left out of the configuration is left out before it counts
- An `externalId` a `fieldMapping` renames is matched on under the target's name, as SFDMU matches it: `ExternalID__c` mapped onto `External_ID__c` upserts on `External_ID__c`
- An entry of a `fieldMapping` that names neither a `targetObject` nor both fields of a pair maps nothing, as in SFDMU, and fails nothing
- `excludedFields` are not written, renamed or not
- Under `useValuesMapping`, the rows of `ValueMapping.csv` for the object become a value mapping rule on their field, named as the target calls it when the export renames that field. A row with no `Value` maps nothing, as SFDMU writes the value as read

## What the import does not carry

The page says each of these, by object, in your language. An object left out is not in the configuration; an object kept runs as Sync runs it.

| In the export                                                                                                                                             | What happens                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `excluded: true`                                                                                                                                          | The object is left out, as in SFDMU                                                                                                                                                                                                                                                                                                                                              |
| `Readonly`, or no `operation`                                                                                                                             | The object is left out: nothing is written to it. SFDMU still reads it to find the related records of the others, and Sync does not                                                                                                                                                                                                                                              |
| An entry with no `query`                                                                                                                                  | Left out, as in SFDMU                                                                                                                                                                                                                                                                                                                                                            |
| An `operation` SFDMU does not know                                                                                                                        | Left out, as SFDMU reads it as `Readonly`                                                                                                                                                                                                                                                                                                                                        |
| `DeleteSource`, `DeleteHierarchy`, `deleteFromSource`, `deleteByHierarchy`                                                                                | Left out. Sync's delete goes to the target and follows no hierarchy: a delete meant for the source would have landed in the target                                                                                                                                                                                                                                               |
| `Delete`, `HardDelete`                                                                                                                                    | Kept as Sync's delete, which differs twice: it goes to the recycle bin, and it takes the target records holding the ids it reads in the source, not what the query selects in the target. **Open in Sync** says what each object does above **Run the sync** and **Simulate**, which both wait until it is read; **Run now** opens such a configuration there rather than run it |
| `Update` with an `externalId`                                                                                                                             | Kept, but Sync's update finds its record by the source record's Id: set it to upsert on an External ID                                                                                                                                                                                                                                                                           |
| `Update` or `Upsert` with no `externalId`                                                                                                                 | Kept, and said: SFDMU then matches on the object's name field, or an auto-number or unique field, and Sync has no such default. An update goes by Id, and an upsert asks for an External ID on its row                                                                                                                                                                           |
| `Upsert` on a field that is no External ID                                                                                                                | Kept, and said: SFDMU matches on any field, Salesforce upserts on an External ID or Id Lookup field only, and a run on another is refused                                                                                                                                                                                                                                        |
| A composite `externalId`, such as `Name;Phone`, or a parent's field                                                                                       | Not carried: Sync matches on one field of the object. An upsert asks for one on its row                                                                                                                                                                                                                                                                                          |
| `master: false`                                                                                                                                           | Not carried: SFDMU copies only the records the other objects need, and Sync reads every record the filter selects                                                                                                                                                                                                                                                                |
| `LIMIT`, `OFFSET`, `ALL ROWS` and the rest of a query                                                                                                     | Not carried, each named. Sync reads every record the filter selects                                                                                                                                                                                                                                                                                                              |
| A WHERE with a subquery, or anything else [Sync's filter refuses](sync.md)                                                                                | Kept on the object's row to rewrite: the save refuses it as it stands                                                                                                                                                                                                                                                                                                            |
| `updateWithMockData` with `mockFields`                                                                                                                    | Sync has no fake data, so the fields are left out of the write rather than copied with their real values. A required field fails its record; take it out of `mockFields` to copy it. With `"name": "all"`, the whole object is left out                                                                                                                                          |
| `deleteOldData`                                                                                                                                           | Not carried: the target's old records are not deleted first                                                                                                                                                                                                                                                                                                                      |
| `objectSets`                                                                                                                                              | Merged into one configuration: SFDMU runs one set after the other, Sync writes them in one run, in the order their lookups decide. A later entry of an object is left out, as a configuration holds an object once                                                                                                                                                               |
| A row of `ValueMapping.csv` with a `/regex/`, an `eval(...)` of any case, or a value SFDMU writes as an empty field: `#N/A`, `null`, `NULL`, `undefined`  | Not applied, and named: a value mapping rule maps one exact value to another, and writes no empty field                                                                                                                                                                                                                                                                          |
| Emails and phone numbers, which SFDMU copies as read                                                                                                      | Neutralized, as every Sync run neutralizes them: every email address under `.invalid`, every phone number a fictional one. Untick **Neutralize emails and phone numbers** under **Run it from Sync** to copy them as read                                                                                                                                                        |
| Any other key, of the file or of an object: `allOrNone`, `bulkApiVersion`, `sourceRecordsFilter`, `skipExistingRecords`, add-ons, a key SFDMU added since | Named, and not read. A key the import does not know never fails it                                                                                                                                                                                                                                                                                                               |
